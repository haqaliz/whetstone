## Task 4 — GREEN: implement the split pin and the flag

**Files:** `src/whetstone/loop/check_probe.py`, `src/whetstone/cli.py`.

- `run_check(run, *, heldout: Path | None = None)`.
- Add `HeldoutUnreadable(ValueError)` to the module and to `REFUSALS`.
- Load with `whetstone.loop.heldout.read_document` and `document_digest_of` by identity; catch
  `OSError` / `json.JSONDecodeError` / the loader's refusals into `HeldoutUnreadable`.
- Load the document **before** reporting the budget violation (refusals come first), then compare
  the recorded digest after the budget pin; a missing/invalid record is a violation.
- CLI: add `--heldout` to the `check-probe` parser (`cli.py:697-705`), pass
  `heldout=args.heldout`, and update the help text.
- `disclosure` may add `expected draws: {K}`; keep the existing lines' text otherwise.
- Update the module docstring: the decision now also checks the declared budget and the committed
  split, and both are **declared-input checks, not new yield thresholds**.

**The CLI's flag-surface guard must move, and it must say why.**
`tests/loop/test_check_probe_cli.py:102-116` currently asserts the parser offers exactly
`--help` and `--run`, with the rationale that no flag may change the decision. `--heldout` does
not add a threshold or a knob; it names the document the split pin compares against, and it can
only add a violation. Re-pin the test to `["--help", "--heldout", "--run"]` and rewrite its
docstring: no flag may set a budget, a seed, a timeout or a pass bar; `--heldout` is a document
pin. Add a test that `--heldout` is not required (the budget pin still decides a run without it).
