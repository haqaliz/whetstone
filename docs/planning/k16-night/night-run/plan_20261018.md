# Plan — the operator run (S1–S3, no code)

**Date:** 2026-10-18 · **Aspect:** `night-run` · **PRD:** `../prd.md` S1–S3

This aspect is **operator-executed after the guards merge**. It adds no production code and no
second command sheet: every command is the existing block in
`docs/planning/p2-rollouts/night-door/runbook.md`, with the one new `--heldout` flag on
`check-probe`.

## Preconditions

- The guards PR is merged to `master`.
- The primary checkout `$REPO` is clean at `master`; `uv run` syncs `0.25.0` (the sheet's
  `uv run`, never `.venv/bin/whetstone` — the direct binary records a stale version).
- The GPU is serialized: no other MLX process, no other night.
- `$DONOR` is the operator's donor checkout for the optional re-mine.
- The operator writes down four declarations before the first command: `PROBE_RUN_ID`,
  `NIGHT_RUN_ID` (distinct, fresh — never `probe-001` / `night-001`), `RUN_SEED`, `RECORDED_ON`.
  None of them is generated by the code.

## Sequence

1. **Probe.** Run the sheet's probe block verbatim.
2. **Probe decision — new flag.**

   ```bash
   uv run whetstone check-probe \
     --run "$REPO/runs/night-probe/$PROBE_RUN_ID" \
     --heldout "$REPO/tasks/heldout/source-b.json"
   ```

   Exit 0 → proceed. Exit 1 → a named violation (control not `PASS` on every draw, empty seed
   map, `draws != sampling.K`, or a held-out digest mismatch); the night **does not run**; write
   the violation into the finding. Exit 2 → a refusal (not a probe run, unreadable ledger,
   incomplete run, unreadable held-out document); fix the command/artefact and re-run the probe
   **fresh** under a new probe id — a killed probe is never resumed.

3. **Night.** Run the sheet's night block verbatim. Do not pass a draw budget; `K = 16` is the
   constant. Do not reuse the probe's id.
4. **Read the ledger back.** From `$REPO/runs/nights/$NIGHT_RUN_ID/ledger.json` confirm:
   `draws == 16`; `task_set.heldout.document_digest` equals the digest of
   `tasks/heldout/source-b.json`; the control arm is `PASS` on every recorded draw; the dataset
   and checkpoint blocks say what the finding will quote. A digest mismatch is a **halt**, never
   a rerun under the changed document.
5. **Leakage (only when a checkpoint exists).**

   ```bash
   uv run whetstone check-leakage \
     --run "$REPO/runs/nights/$NIGHT_RUN_ID" \
     --heldout "$REPO/tasks/heldout/source-b.json" \
     --checkpoint "$REPO/checkpoints/$NIGHT_RUN_ID"
   ```

   Exit 0 → proceed. Exit 1 → a named leak; halt at the source and write it into the finding.
   Exit 2 → refusal; halt and name it.

6. **Gate (only after leakage exits 0).** Materialize the untrained incumbent exactly as the
   gate runbook does (`docs/planning/p3-promotion-gate/gate-runbook/runbook.md:117-129`), then run
   the gate command with `--candidate "$REPO/checkpoints/$NIGHT_RUN_ID"` and the incumbent path.
   Exit 0 `promoted` / 1 `rejected` / 3 `UNVERIFIED` are all valid and are written verbatim into
   the finding. Exit 2 is a refusal: fix and re-run, never reinterpret.
7. **Finding.** Copy `docs/planning/k16-night/finding-template.md` to
   `docs/planning/k16-night/finding.md`; fill it from the ledger, not from memory. The JSON
   evidence block must carry exactly: `run`, `probe`, `draws`, `heldout_document_digest`,
   `denominator`, `selected`, `unverified`, `coverage`, `checkpoint`. Section 4 must state that
   `donor-a-c6e4d4c4de87` is a held-out member and therefore excluded, so a zero is not read as
   clean evidence about the budget alone. Section 6 must state that the 12 `NO_ORACLE` tasks were
   drawn and cannot yield an example under the sealed budget.
8. **Check the finding.**

   ```bash
   uv run pytest tests/test_k16_night_finding.py -q
   ```

   The live guard reads the primary's run through git's common dir. Green → the quoted counts
   equal the ledger's.
9. **Commit and merge.** Update `docs/STATUS.md` (a new top entry, never an edit of the guards
   entry) and `CHANGELOG.md` with the night's outcome. Commit the finding and the write-up on
   `feat/k16-night/aliz`, then merge.

## The two outcomes

**A checkpoint exists.** M1's exit criterion is met: the night selected at least one strict-PASS
and wrote both documents. Leakage and the gate are the next steps. `card`/`fuse` are mechanically
reachable but belong to M3; the § 3 baseline spend and the P4 honest-number report remain the
later operator chain (`docs/ROADMAP.md` § 12). Do not claim a delta.

**No checkpoint.** The finding records the ledger's own `checkpoint.absent` reason and the
per-draw counts, accepts the zero, and names the held-out confound. No representation change, no
looser verifier, no split move. *"Accept the finding"* is a legitimate outcome
(`docs/ROADMAP.md:790`).
