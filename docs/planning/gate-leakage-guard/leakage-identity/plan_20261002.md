## Phase 1 — Identity extraction and overlap by sha12 (RED first)
- **Goal:** `check_overlap` matches on the trailing 12-hex identity; an id with none is refused.
- **Files:** `tests/loop/test_check_leakage.py` (tests first), `src/whetstone/loop/check_leakage.py`.
- **Tests first (spec AC 1, 2, 3, 5):**
  1. disjoint sha12 sets -> clean.
  2. **Adversarial:** training `legacy-a-aaaaaaaaaaaa` vs held-out `donor-a-aaaaaaaaaaaa` -> leak naming
     both ids; the same fixture asserted CLEAN under a local copy of the old exact-string rule
     (so the test demonstrably fails the old check).
  3. a training id with no trailing 12-hex -> new refusal `UnrecognisedIdentity` (added to `REFUSALS`).
  4. a held-out member with no recognisable sha12 -> the same refusal.
  5. same sha12 in the public source is not compared.
- **Implement:** a small `_identity(task_id) -> str` (regex `[0-9a-f]{12}$`); `check_overlap`
  compares identities; the leak report names the training id and the held-out id it matched.
- **Validation:** `uv run pytest tests/loop/test_check_leakage.py -q` green; ruff + mypy clean.
- **Commit:** `leakage-identity: overlap by sha12, so a re-mint cannot hide a leak (TDD)`
