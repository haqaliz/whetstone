## Phase 1 — The renderer and the parser (pure functions)

**Goal:** the numbered-listing prompt text and the `EDIT`-block parser, deterministic and
never-repairing. **Prerequisites:** green suite; `uv sync` done.

**Files:** create `src/whetstone/bakeoff/line_range.py`; create
`tests/bakeoff/test_line_range.py`.

**What the code must do**
- `render_line_range_prompt(task, sources)`: for each oracle source file (paths from the same
  `sources.oracle_sources` machinery the standard renderer uses), read its lines at
  `base_commit` (read-only, via the same repository reader; `locatability.checkout_reader`-style
  escapes: refuse absolute paths, `..`, symlinks leaving the checkout) and render
  `path` followed by `N: <line>` for each line, 1-based. Then the response-format section:
  "Address a line range and write the replacement text. One or more blocks:
  `EDIT <path>:<start>-<end>` then `<<<<<<< REPLACE` / replacement / `>>>>>>> END`." Byte
  deterministic: no sets/dict-iteration/clock/fs-order dependence (`rendering.py:25-36` rule).
  A held test path (any path in `task.test_blobs`, case-folded and exact) is refused by name —
  never rendered into the prompt (the `HeldTestInSources` precedent). No inference imports;
  the module is stdlib-only.
- `parse_edit_blocks(text)`: returns a list of blocks `(path, start, end, replacement)` or a
  named refusal for the whole completion: `MALFORMED` with a reason (`missing path`, `missing
  range`, `unparsable range`, `unclosed replacement`, `missing marker`). Never repairs: a block
  with any defect refuses the completion; no block is dropped while others proceed.

**Validation:** `uv run pytest tests/bakeoff/test_line_range.py` green; `uv run pytest` green.
**Commit:** `line-range: the numbered-listing renderer and the EDIT-block parser (TDD)`

## Phase 2 — The scoring seam and the measurement driver

**Goal:** an injectable renderer on `scoring.score` whose default is byte-identical, and the
driver that spends the bake-off without entering the verifier. **Prerequisites:** phase 1.

**Files:** modify `src/whetstone/bakeoff/scoring.py` (one keyword parameter, default
`render_prompt`); create `src/whetstone/bakeoff/measure.py`; create
`tests/bakeoff/test_measure_driver.py`.

**What the code must do**
- Seam: `score(..., renderer=None)` — `renderer or render_prompt`. Existing callers unchanged;
  a test asserts a byte-identical prompt reaches the generator under the default (the existing
  suite green is the guard).
- Driver `run_measurement(...)`: reads the stratum document and the held-out document (by
  digest, both committed), computes the population as `membership(stratum) −
  membership(heldout)`, and **refuses (exit 2) unless the result equals the pinned list**
  (spec's 16 ids, a constant in the module). For each task in the pinned order (sorted by id):
  render the numbered-listing prompt, generate one greedy completion (the `Generator` seam;
  `sampler_for(1)` is greedy by identity — never sample), record the completion to the
  transcript codec and a rollout row to the journal codec with `outcome = Outcome.UNVERIFIED`
  and `detail` stating "measurement run — no grading performed by design". No call to
  `verify_strict`/`verify_weak` for any rollout (asserted by seam spy). Run the control arm
  (inert patch + reference patch, the same probe `draws._control` builds) through the verifier;
  if the control fold is not `PASS` on every draw, refuse (exit 2) and write no evidence.
  Write the run manifest (JSON, schema `whetstone-measure/1`): run id, recorded-on, candidate
  repo id + immutable revision, seeds, the task list (the pinned ids), the stratum/held-out
  document digests, `prompt_sha256` of every rendered prompt (via `rendering.prompt_hash`),
  control status per draw, tool versions. `--workspace` must be an absolute path; journal and
  transcript default to `runs/edit-contract-finding/{journal.jsonl,transcript.jsonl}`. Exit 0
  only when manifest, journal and transcript are all written. Everything model-free in tests:
  the stub generator returns a fixture completion per task.
- The CLI (`python -m whetstone.bakeoff.measure`): `--tasks <corpus dirs>...` (for loading the
  stratum/held-out documents and oracle sources), `--stratum <path>`, `--heldout <path>`,
  `--weights <root>` (verified offline, `weights.py`), `--only <repo id>`, `--workspace`,
  `--journal`, `--transcript`, `--manifest`, `--recorded-on`, `--timeout`. No `--out` into
  `reports/` (counts never published).

**Validation:** `uv run pytest tests/bakeoff/test_measure_driver.py` green; full suite green.
**Commit:** `measure: the numbered-listing driver, population-pinned, verifier never entered (TDD)`

## Phase 3 — The addressability instrument and the decision

**Goal:** the offline classifier with the pre-committed rule, exposed as a command exit.
**Prerequisites:** phases 1–2 (parses the format; reads the manifest + transcript).

**Files:** create `src/whetstone/bakeoff/addressability.py`; create
`tests/bakeoff/test_addressability.py` and `tests/bakeoff/test_addressability_cli.py`.

**What the code must do**
- Classification (stdlib-only, no model, offline): per completion, parse with
  `parse_edit_blocks`; for each block, resolve the path at `base_commit` (materialise a
  checkout in a tempdir, `locatability`-style, with the same escape rules), read the file's
  line count; classes per the spec, worst-first per rollout; `ast.parse` on each replacement
  text (syntax only); sub-counts (a) replacements that parse but the file would not import,
  (b) blocks addressing a path outside the oracle listing's set — reported beside the
  partition, never moving a class.
- Decision: `_RULE = "GO iff count(ADDRESSABLE) * 2 > population"` — a constant, cross-pinned
  into the output document's rule sentence (the `locatability` pattern); population = the
  manifest's task list, verified equal to the pinned list by identity (else refusal).
- Command: `--manifest`, `--transcript`, `--tasks`, `--stratum`, `--heldout`, `--out` (writes
  `runs/edit-contract-finding/addressability.json`, schema `whetstone-addressability/1`, with
  the partition, sub-counts, the rule sentence and the population). Exits: 0 GO, 1 NO-GO, 2
  refused (missing manifest/transcript, empty population, task-set mismatch, unreadable
  corpus) — refusal prints a named reason to stderr and writes nothing. Determinism test:
  same inputs → byte-identical output.

**Validation:** `uv run pytest tests/bakeoff/test_addressability.py tests/bakeoff/test_addressability_cli.py` green; full suite green.
**Commit:** `addressability: the offline instrument and the pre-committed decision rule (TDD)`

**What the finding must state:** the decision (GO/NO-GO) and the exit; the population size;

Adversarial criteria in force (the aspect's "what it rejects"): the measurement can never be
read as a win — no recorded outcome is a covered verdict, the verifier is never entered, and a
run whose control arm failed produces no evidence and no verdict. "The instrument accepts an
addressable completion" is half a test; the refused classes, the worst-first order, the
denominator-staying `UNCLASSIFIED` and the exit-2 refusals are the other half.

## Environment, determinism & locality

- No environment variables; no network: the driver and instrument are offline; the model runs
  with `HF_HUB_OFFLINE=1` against local weights (the `mlx_engine` precedent). Weights at the
  primary checkout by absolute path (machine-level, never per-worktree).
- Determinism: fixed run seed; task order sorted by id; `prompt_sha256` recorded per prompt;
  the instrument is a pure function of (manifest, transcript, task documents) with a
  byte-identical-output test.
- Held-out boundary: held-out members are subtracted from the population by identity and the
  driver refuses any deviation; no held-out member is ever a rollout target, and nothing this
  unit does can reach the training set (it trains nothing).
- Locality: the run and the instrument run entirely on this machine; nothing leaves the box.

## Edge cases & error handling

- **Control arm not intact** → exit 2, no evidence, no verdict (the instrument would refuse
  anyway — double-guarded).
- **Population mismatch** (document digest changed, stratum membership changed, run recorded a
  different task set) → driver and instrument both refuse by name (exit 2). A changed
  pre-committed input is a halt, never a rerun.
- **Evidence unreachable** (missing manifest/transcript, missing task document, unreadable
  corpus) → `UNCLASSIFIED` stays in the denominator; a refusal exits 2 with a named reason.
- **Instrument input determinism** — same inputs, byte-identical output; a test asserts it.
- **NO-GO outcome** → the unit ends at phase 4's merge; phases of the contract aspect are not
  planned, not built, no amendment. This is a valid, publishable result (the `finding.md`
  disclosure pattern; `docs/ROADMAP.md` § 13).
