# Implementation plan — probe-backend-pin / probe-door

**Date:** 2026-10-29 · **PRD:** `../prd.md` · **Spec:** `spec.md`.

## Phase 1 — The check (`run_check`, report, disclosure)

**Files:** `src/whetstone/loop/check_probe.py`, `tests/loop/test_check_probe.py`.

**RED:**

1. `test_a_matching_backend_pin_proceeds`: `run_check(_probe_run(...), runtime="torch",
   device="mps", precision="float16")` → proceed, `report.backend["name"] == "torch"`,
   `report.pins` carries the three.
2. `test_each_backend_mismatch_is_a_named_violation` (parametrized runtime/device/precision):
   each mismatch → proceed False, the violation names both sides.
3. `test_a_pin_without_a_recorded_backend_is_a_violation`: the `unsealed` v2 fixture with the
   `backend` key deleted; any pin → a violation naming the missing block, never a refusal.
4. `test_the_disclosure_shows_pins_and_the_recorded_backend`: the two lines.
5. `test_no_pin_is_the_old_decision`: the existing valid probe without pins still proceeds and
   `report.pins == ()`, `report.backend` is the fixture's record (read-only).

**GREEN:**

- Add `runtime`, `device`, `precision` keyword-only params.
- After the held-out pin, build `pins = tuple((name, value) for ... if value is not None)`;
  when non-empty, read `payload.get("backend")`:
  - not a `Mapping` → `_report(proceed=False, violation="the ledger records no backend ...")`;
  - `runtime` → `family(recorded_name)` vs `family(runtime)`; an `UnknownRuntime`/missing name
    is a violation naming the recorded value;
  - `device`/`precision` exact; a mismatch names both.
- `ProbeReport` gains `backend: Mapping[str, Any] | None = None` and
  `pins: tuple[tuple[str, str], ...] = ()`; `_report` accepts optional `pins` and sets
  `backend` from the payload when it is a mapping.
- `disclosure` prints `pins: ...` and `backend: ...` when present.

**Validation:** `uv run pytest tests/loop/test_check_probe.py -q` green.
