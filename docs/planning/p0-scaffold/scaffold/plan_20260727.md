## 2. Implementation Phases

### Phase 1 — Bootstrap: packaging + the first RED test

**Goal:** a minimal installable package and a failing test, in that order of *authoring* but
test-first in each cycle.

**Prerequisites:** none.

**The awkward bootstrap moment** (spec § risk 1): `importlib.metadata.version("whetstonehq")`
requires the project to be **installed**, so the very first test cannot pass before a
`pyproject.toml` exists. Resolution: author `tests/test_version.py` FIRST and watch it fail
with `ModuleNotFoundError` (a real RED), then create the minimum `pyproject.toml` +
`src/whetstone/__init__.py` + `uv sync` to turn it GREEN.

**Files:** `tests/test_version.py`, `pyproject.toml`, `src/whetstone/__init__.py`,
`.python-version`, `uv.lock`

**Validation:** `uv run pytest tests/test_version.py` exits 0. Covers **AC-3**.

### Phase 2 — The CLI

**Goal:** `whetstone --help` and `--version` work; bare `whetstone` fails loudly.

**Prerequisites:** Phase 1.

**Design** (the sibling project convention): stdlib `argparse`, single `cli.py`, `main(argv: list[str] |
None = None) -> int` so tests call it directly and assert exit codes. `prog="whetstone"`. **No
subcommands** (PRD Decision 5). Bare invocation prints usage to stderr and returns non-zero.

**TDD order:**
1. RED `test_help_returns_zero_and_names_the_program` → **AC-1**
2. RED `test_version_flag_prints_the_resolved_version` → **AC-4a**

4. RED `test_the_parser_actually_exposes_help_and_version` → **AC-7**, the anti-vacuity control
5. GREEN: implement `cli.py`

**⚠️ Mandatory for AC-7:** before trusting it, temporarily point the introspection at an empty
`ArgumentParser()`, run the test, **observe it FAIL**, then revert. Record the observation in
the commit body. A guard nobody has seen fail may be passing vacuously.

**Files:** `tests/test_cli.py`, `src/whetstone/cli.py`

### Phase 5 — CI, with the mlx tripwire

**Goal:** CI green on `master`, and the mlx question answered empirically.

**Prerequisites:** Phases 1–4.

**Workflow shape** (mirrors the sibling project's, plus mypy which the sibling project lacks):

```yaml
name: CI
on:
  push: { branches: [master] }
  pull_request: { branches: [master] }
concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true
jobs:
  test:
    name: test (macOS)
    # mlx-lm declares `mlx; platform_system == "Darwin"`. Off Darwin it installs
    # SUCCESSFULLY with no engine behind it — a green run that proves nothing.
    # macOS is the only runner on which this check can mean anything.
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v5
        with: { enable-cache: true }
      - run: uv python install 3.12
      - run: uv sync
      - run: uv run ruff check .
      - run: uv run mypy src/
      - run: uv run pytest
      - name: mlx resolves and imports on this runner
        run: |
          uv sync --extra mlx
          uv run python -c "import mlx.core; print(mlx.core.__name__)"
```

**Validation:** the workflow run is green. **AC-9, AC-10.**

**⚠️ Expect iteration here.** This is the phase most likely to need debugging, and the mlx step
is the one carrying real information. If it fails, **that is a finding, not a defect to paper
over** — report it rather than deleting the step.

## 4. Testing Strategy

**Unit** — `test_version.py` (metadata boundary), `test_cli.py` (help/version/bare + the
anti-vacuity control), `test_packaging.py` (LICENSE, CHANGELOG).

**Integration** — `test_console_script.py`: a real subprocess proving `pyproject.toml`'s entry
point resolves. The only test that exercises the installed artifact rather than the source.

**Manual** — `uv run whetstone --help`; `uv run whetstone --version`; `uv run whetstone`
(expect usage + non-zero); `git clone` to a temp dir + `uv sync` + `uv run pytest`.

**Commands:** `uv run pytest` · `uv run ruff check .` · `uv run mypy src/`

**Adversarial / anti-vacuity.** P0 ships no reward, so there is no cheating policy to defend
against; the transferred obligation is that no guard passes over an empty set. **AC-7 must be
watched failing** (point it at an empty parser, observe FAIL, revert) and the observation
recorded in the commit body. AC-10 carries the same discipline: it asserts `import mlx`, not
install-exit-0, because `mlx-lm` installs *successfully without the engine* off Darwin.

**Determinism.** Every test is pure — no network, no wall clock, no randomness, no model call.
`tmp_path` for any filesystem work. Nothing in P0 has a seed to pin because nothing trains.

## 5. Environment, Determinism & Locality

- **Env vars:** none. P0 needs no BYOK key — nothing calls a model.
- **External services:** none at runtime. CI uses GitHub-hosted `macos-latest`.
- **Local setup:** `uv sync`, then `uv run pytest`.
- **Determinism:** `uv.lock` committed; `.python-version` pinned to 3.12. `macos-latest`
  deliberately unpinned so the mlx step acts as a drift tripwire (PRD risk 2).
- **Train/held-out boundary:** **not applicable** — P0 has no training data, no eval set, and
  no held-out split. Nothing can leak because nothing exists to leak. Stated explicitly rather
  than skipped.
- **Locality:** nothing leaves the machine. CI runs against the repo's own public source; no
  user task data exists yet. No egress.

## 6. Edge Cases & Error Handling

| Case | Outcome |
|---|---|
| `importlib.metadata.version("whetstonehq")` raises `PackageNotFoundError` (running from source without an install) | Let it raise with a clear message naming `uv sync`. **Do not** fall back to a hardcoded literal — that is exactly the sibling project's `0.0.0`-vs-`0.7.0` drift, and a silently-wrong version is worse than a loud failure |
| Bare `whetstone`, no args | Usage to stderr, **non-zero** exit. Never exit 0 — a no-op success is a claim nothing happened correctly |
| `uv sync` before `pyproject.toml` exists | Expected during Phase 1 bootstrap only |
| mlx step fails in CI | **Report it as a finding.** It would mean the locked MLX/Apple-Silicon direction needs revisiting in P1, which is precisely why the step exists. Do not delete the step to go green |
| `macos-latest` repoints past available mlx wheels | The mlx step fails and tells us. Intended behaviour |

**No `UNVERIFIED` path applies** — P0 has no verifier and no gate. Stated explicitly so its
absence reads as scoped-out rather than forgotten.

## 7. Agent Execution Notes

**Parallelization:** Phase 6 (docs) is fully independent and can run concurrently with Phases
1–5. Phases 1→2→3→4→5 are strictly sequential — each needs the prior one's artifacts.

**Human review checkpoints:**
1. After Phase 2 — the CLI's shape is the one design decision with lasting consequence.
2. After Phase 5 — **the first real CI run**, and the first empirical answer on mlx.

**Likely to need iteration:** Phase 4 (mypy `strict` on a fresh package usually surfaces a few
missing annotations) and Phase 5 (CI config rarely works first try).

**Ask before proceeding if:** the mlx step fails (a finding, not a bug to hide); `uv sync`
cannot install the project editable, breaking the metadata lookup; or mypy `strict` demands a
design change to `cli.py` rather than mere annotations.

**Do not:** add runtime dependencies (keep `dependencies = []`), import any inference library
under `src/whetstone/` (P1's guard will fail the build), add subcommand stubs, or weaken a
check to make a phase pass.
