## Phase 1 — The transcript record and its writer

**Goal.** A durable, append-only, replayable record of one generation.

**Prerequisites.** None.

**Files**
- create `src/whetstone/bakeoff/transcript.py`
- create `tests/bakeoff/test_transcript.py`

**Design.** Mirror `journal.py` deliberately — same JSON-Lines shape, same field-by-field
`_encode`/`_decode` (`journal.py:134-167`, and its docstring at `:136-140` explaining why
`dataclasses.asdict` was refused), same "an unreadable line raises rather than being skipped"
rule (`journal.py:121-129`). A second serialisation style in the same package would be a second
set of failure modes to learn.

```
Transcribed:  candidate, task_id, prompt_sha256, prompt, completion
Transcript:   path; append(record); replay() -> Mapping[(candidate, task_id), Transcribed]
```

Keyed `(candidate, task_id)` like the journal (`journal.py:44`). A repeated key takes the last
record, matching `journal.py:110-113`.

**Tests (write first)**
1. A written record round-trips through `replay()` byte-identically, including a completion with
   newlines, backticks, and a trailing `\n`.
2. A truncated final line raises `TranscriptUnreadable`, never a silent skip — the anti-vacuity
   shape `journal.py:47-52` uses.
3. `replay()` on a missing file returns empty (the ordinary first run), distinguishably from a
   corrupt one.
4. Appending twice for one key yields the later record.

**Validation.** `uv run pytest tests/bakeoff/test_transcript.py -q`

**Commit.** `Keep what the model actually wrote`

## Phase 2 — `RecordingGenerator`, the wrapper

**Goal.** Capture prompt and completion without widening the model seam.

**Prerequisites.** Phase 1.

**Files**
- modify `src/whetstone/bakeoff/transcript.py` (add the wrapper)
- create `tests/bakeoff/test_recording_generator.py`

**Design.** `RecordingGenerator` implements `Generator` — one method, `generate(prompt) -> str`
(`generator.py:59`). It delegates, records, and returns the inner completion **unchanged**. It is
constructed per `(candidate, task)` so it knows what to key on; `sweep.py` already iterates that
pair, which is where it gets built.

**Tests (write first — AC1, AC2)**
1. `isinstance(RecordingGenerator(stub, sink), Generator)` — the protocol is `runtime_checkable`
   (`generator.py:46`), and the existing suite compares signatures too, so do the same here.
2. **Passthrough is byte-exact** for: a normal diff, prose with no diff, `""`, and a completion
   containing a fenced block. Watched failing against a wrapper that `.strip()`s.
3. One call writes exactly one record carrying the right candidate, task id, prompt, and
   `prompt_sha256` matching `prompt_hash` (`rendering.py`).
4. An inner generator that raises writes **no** record and propagates the exception.

**Validation.** `uv run pytest tests/bakeoff/test_recording_generator.py -q`

**Commit.** `Watch the seam without widening it`

## Phase 3 — Composition with `Sealed`, and the wiring

**Goal.** The recorder reaches a real run, and a refused prompt is not recorded.

**Prerequisites.** Phase 2.

**Files**
- modify `src/whetstone/bakeoff/run.py` (add `--transcript`, wrap the engine)
- modify `tests/bakeoff/test_run.py` (or add `tests/bakeoff/test_run_transcript.py`)

**Design.** `--transcript PATH`, **undefaulted**, exactly like `--journal`
(`run.py:587-592`: *"a default would resume from a run somebody had forgotten"*). Same reasoning,
sharper: a default transcript path would write the user's private donor code somewhere nobody
chose.

Composition order is `Recording(Sealed(engine))` — Recording **outside**. `Sealed` refuses any
prompt whose digest is not in the frozen contract (`run.py:180-208`), and a refusal is not a
generation; recording it would put a completion-less row in a file whose whole purpose is
completions.

**Tests (write first — AC3)**
1. Composed as above, a prompt outside the frozen contract raises `ContractChanged` **and** the
   transcript is empty. Watched failing against `Sealed(Recording(engine))`, which records first
   and would leave a row behind.
2. With no `--transcript`, behaviour is byte-identical to today — no file created, existing run
   tests unchanged.
3. `--transcript` pointing under `--out` is a **usage error**, not a warning (AC6): `--out` is
   committed, and for source B a completion quotes private donor code. Mirrors
   `run.py:551-557`'s existing refusal shape for `--workspace`.

**Validation.** `uv run pytest tests/bakeoff/ -q`

**Commit.** `Let an operator choose where the transcripts land, or not have them`

## Phase 4 — Offline replay and the cause breakdown

**Goal.** Turn stored completions into an attributed breakdown, with no model.

**Prerequisites.** Phase 1. (Independent of Phases 2–3 — **can run in parallel**.)

**Files**
- create `src/whetstone/bakeoff/attribution.py`
- create `tests/bakeoff/test_attribution.py`

**Design.** Two layers, because they have different costs and different dependencies:

- **Pure layer (no checkout).** Re-run `extract_patch` over each stored completion. Every
  `NoDiff` is attributed by `patch.py`'s **own reason string** — `patch.py:158,174,180,184` are the
  four construction sites, and the reasons already name "no fenced block", "a diff header was
  found but no hunk", and the truncated-before-first-hunk case. **The taxonomy is read from those
  sites, never re-invented here** (spec AC5; PRD § 8 flags an invented taxonomy as 🔴). A test
  asserts every `NoDiff` construction site in `patch.py` maps to exactly one bucket, so a new
  reason added there fails this test rather than falling into an "other" bin.
- **Checkout layer.** For an `Extracted` diff, distinguish *git would not parse it* from *git
  parsed it and would not apply it*. These are `verify/repo.py:100` (`--numstat` failed) versus
  `:118` (apply failed) — the same two calls STRICT makes at `strict.py:171` and `:180`. Used
  **read-only**; `verify/` is not modified (AC8).

**Tests (write first — AC4, AC5)**
1. A transcript of a known completion re-extracts to the same `Extraction` the live path produces
   — asserted by calling the *same* `extract_patch`, not a copy.
2. Each of `patch.py`'s four `NoDiff` reasons lands in its own bucket; a synthetic fifth reason
   fails the mapping test loudly.
3. A well-formed diff against a missing path is attributed *parsed-but-did-not-apply*, and a
   corrupt-mid-hunk diff is attributed *would-not-parse* — the two causes `reports/baseline/`
   cannot currently separate.
4. **No `mlx` import anywhere in the module or its test** — assert by AST walk, the shape
   `tests/test_no_inference_on_reward_path.py` already uses.

**Validation.** `uv run pytest tests/bakeoff/test_attribution.py -q`

**Commit.** `Say which zero it was`

## Phase 5 — The reproduction check, and the locality guard

**Goal.** Compare arm A against the committed record; prove the transcript cannot be committed.

**Prerequisites.** Phase 4.

**Files**
- modify `src/whetstone/bakeoff/attribution.py` (the comparison)
- create `tests/bakeoff/test_reproduction.py`
- create `tests/bakeoff/test_transcript_locality.py`

**Design.** The comparison reads `reports/baseline/report.json` — the committed record — and a
replayed arm-A result, and reports per `(candidate, task_id)`: agreed, or diverged with both
outcomes. It **returns** the divergences; it does not decide what to do about them. PRD D2a makes
divergence a slice-halting finding, and that judgement belongs to the operator reading the list,
not to a function that could quietly tolerate a threshold.

**Tests (write first — AC6, AC7)**
1. A replay agreeing with a fixture report yields no divergence.
2. One flipped outcome is reported, naming both sides. Watched failing against a comparison that
   returns `[]`.
3. A candidate or task present in one and absent from the other is a divergence, **not** a skip —
   a missing row is exactly how a partial run reads as agreement.
4. `git check-ignore` reports the documented transcript root as ignored (the shape
   `tests/test_tasks_layout.py` uses, with its trailing-slash trap in mind:
   `test_the_trailing_slash_form_is_load_bearing`).
5. `reports/` still holds exactly the three baseline artifacts — `tests/bakeoff/test_report.py:961`
   passes **unchanged**, proving this aspect published nothing (AC9).

**Validation.** `uv run pytest tests/bakeoff/ tests/test_tasks_layout.py -q`

**Commit.** `Check the rerun against the record before believing either`

## Testing strategy

- **Determinism, no network, no model.** Every test here uses `StubGenerator`
  (`generator.py:73`) or a fixture transcript. Nothing imports `mlx`; Phase 4 asserts that by AST
  walk. No wall-clock dependence — the transcript carries no timestamp for the same reason
  `run.py` takes `--recorded-on` as an input rather than reading a clock.
- **Adversarial coverage.** This aspect does not change the reward, so it carries no cheat
  fixture. Its honesty-property tests are: passthrough is byte-exact (a recorder that normalised
  would corrupt the evidence), a refused prompt leaves no record, a missing row is a divergence
  rather than agreement, and the transcript cannot be committed. Each is watched failing against
  the credulous implementation named in its phase.
- **Anti-vacuity.** Phase 4's bucket-mapping test asserts the set of `NoDiff` sites in `patch.py`
  is non-empty and fully covered, so it cannot pass by observing nothing
  (`CONTRIBUTING.md:56-60`).

## Environment, determinism, locality

- No new dependency, no env var, no key. Nothing in this aspect calls a cloud model.
- **The arm-A run** (operator step, after this lands) is offline: `HF_HUB_OFFLINE` is set by
  `run.py:382`, weights are local (13 GB under `weights/`, sha256 re-checked by `load_weights`),
  and all 66 manifests are local. Greedy decoding, no seeds — which is what makes AC7's
  reproduction check meaningful.
- **Train/held-out boundary:** untouched. Nothing trains here, and the held-out split does not
  exist yet (`PREREGISTRATION.md` § 7.1, open until P3). No data leaves the machine; the transcript
  is the one new artifact and Phase 5 proves it is gitignored.

## Edge cases and error handling

| Case | Outcome |
|---|---|
| Transcript file corrupt / truncated line | `TranscriptUnreadable`, never a skip |
| `--transcript` under `--out` | Usage error before any generation |
| `--transcript` absent | Run behaves exactly as today |
| Inner generator raises | No record; exception propagates |
| Replay finds a task in the report but not the transcript | **Divergence**, never agreement |
| Checkout unavailable for the parse/apply split | That rollout is attributed *unattributed*, named as such — never folded into a neighbouring bucket |
| A new `NoDiff` reason added to `patch.py` later | Bucket-mapping test fails loudly |
