## Task 1 — RED: the flag and the clean refusal

**Files:** `tests/loop/test_night_cli.py`, `tests/loop/test_arm.py`,
`tests/loop/test_backend.py`.

- Parser: `build_parser()`'s `run` and `train-arm` subparsers expose `--runtime` with choices
  exactly `{backend.MLX, backend.TORCH}` (import `backend` in the test).
- `run --night --runtime torch` passes `prefer="torch"` to `run_night` (monkeypatch
  `night.run_night` to capture kwargs); `--runtime mlx` likewise; no flag passes `None`.
- A mixed-environment `AmbiguousBackend` is exit 2 with `whetstone run:` on stderr and no
  traceback; a `NoBackend` likewise. Simulate by monkeypatching the `detect` used in
  `night.run_night` (or `backend._present`) to raise, not by installing runtimes.
- `train-arm --runtime torch` passes `prefer="torch"` to `run_arm`; its `AmbiguousBackend` is
  exit 2.
- `backend.choose(prefer="torch")` on a present set `{"torch"}` returns `torch`; on `{"mlx"}`
  raises `NoBackend`; on both with no prefer raises `AmbiguousBackend`.

Watch them fail.

**Files:** `src/whetstone/cli.py`, `src/whetstone/loop/night.py`,
`src/whetstone/loop/arm.py`.

- Parser: add the flag to both subparsers (literal choices; help names the ambiguity).
- `run_night(..., prefer: str | None = None)`: `runtime = backend_runtime.detect(prefer=prefer) if
  runtime is None else runtime`.
- `run_arm(..., prefer: str | None = None)`: the same one line.
- Handlers: `prefer=args.runtime` on both `conduct_night(...)` and `run_arm(...)`.
- `night.py`: import `AmbiguousBackend`/`NoBackend` from `whetstone.loop.backend` (module scope is
  fine here; `night` already imports `backend`) and add them to `REFUSALS`. The `run --night`
  handler's existing `except REFUSALS` then returns 2.

Run the targeted tests; green.
