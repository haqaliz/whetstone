## Phase 2: The Retry wrapper

- **Goal:** `Retry` — bounded, trigger-gated, exception-transparent, deterministic.
- **Prerequisites:** Phase 1.
- **Files:**
  - `src/whetstone/bakeoff/retry.py` — `Retry` (a `Generator` wrapper): fields `inner:
    Generator`, `budget: int = 2`, `decide: Callable[[str], Trigger | None]` (defaults to
    `trigger_of(classify_completion)` — import the function, don't reimplement); `generate`
    per spec B2/B4: attempt loop, `inner.generate` per attempt, decision after each,
    return the last completion. The transcript's attempt/decision fields are the recorder's
    concern (Phase 3 wiring), not the wrapper's — but the wrapper must return enough for the
    recorder to distinguish attempts; the clean pin: **the wrapper's `inner` IS the
    recorder**, so records are written per attempt by construction and the wrapper only
    decides. (`generate` returns the decided completion; the record follows the generation.)
  - `tests/bakeoff/test_retry.py` (extend, RED first):
    - No-trigger: one generation, returned unchanged.
    - Trigger + budget: exactly `1 + budget` generations; each retry prompt is
      `retry_prompt(first_prompt, trigger)`; the last completion is returned.
    - Trigger stops after budget: with a stub that always triggers, generations == 3, no
      infinite loop.
    - Non-trigger after a retry stops early: budget not fully spent.
    - Exceptions propagate: `UnstubbedPrompt` from `inner` is not caught
      (`sweep.py:109-112` discipline).
    - Determinism: same stub table, two wrapper instances, byte-identical generation
      sequence.
    - `end-of-output` and `im-start-loop` verdicts never retry (cross-check with aspect 1
      fixtures).
- **Validation:** `uv run pytest tests/bakeoff/test_retry.py`
- **Commit:** `Add the budgeted retry wrapper on the generator seam`

## Phase 3: Freeze extension + run.py composition + seal-held proof

- **Goal:** every retry prompt is frozen before anything runs; the composed generator
  enforces it; a mid-run template edit aborts.
- **Prerequisites:** Phase 2.
- **Files:**
  - `src/whetstone/bakeoff/run.py`:
    - `freeze` (`:408-450`) — after each task's first-attempt prompt is posed, also pose
      `retry_prompt(first_prompt, trigger)` for every trigger in the vocabulary
      (`setdefault` into the same `posed` map; the contract SHA then covers them).
    - The entrant loop (`:546-556`) — compose `Retry(Recording(Sealed(engine)))`: build
      `Sealed(engine, contract)`, wrap in `Recording(...)` (existing call, now inside
      Retry), wrap in `Retry(budget=RETRY_BUDGET)` when retries are enabled; when
      disabled (default off until the arm opts in), the composition is exactly today's.
      The `Retry` wrapper reads its trigger mapping + vocabulary from `retry.py`; the
      recorder derives each attempt's `task_id` from its prompt hash via `contract.posed`
      (existing mechanism — retry prompts map to the same task).
  - `tests/bakeoff/test_retry_seal.py` (RED first):
    - Seal-held: freeze a task set, stub the engine, run the composed generator; every
      prompt issued (first + retries) has its hash in `contract.posed` — asserted by
      instrumenting the stub.
    - Mid-run edit: freeze, then mutate the retry vocabulary (monkeypatch a different
      diagnosis sentence), run — `ContractChanged` raises and the run stops (mirror the
      existing seal test's shape for first-attempt prompts).
    - Replay: a recorded run's `Transcript.replay()` returns exactly the decided
      completions, each with `decision == "graded"`, earlier attempts `decision ==
      "retry"`, and `attempt` indices 0..n.
  - `tests/bakeoff/test_run_transcript.py` — extend for multi-attempt records (a retry run
    writes 3 records for one key; locality/refusal invariants unchanged).
- **Validation:** `uv run pytest tests/bakeoff/test_retry_seal.py

- **Commit:** `Freeze the retry prompts and compose the sealed retry loop`

## Edge cases / error handling

- Budget exhaustion is a *recorded outcome*, not an error: the decided completion is the
  last attempt's, and the transcript shows `attempt` 0..2 with the last `graded`.
- `ContractChanged` during a retry: the run aborts (existing discipline) — the attempts
  already recorded stay (append-only), and `replay()` still returns the last record per
  key; the journal's divergence machinery reports the incomplete run.
- A retry prompt colliding with another task's prompt: `setdefault` keeps the first task
  (the existing collision rule, `run.py:443-446`) — two tasks posing one prompt share an
  answer, and retry prompts follow the same rule.
- The retry wrapper must not be composed when `--transcript` is absent (no recorder): the
  composition guard is `kept is not None` — retries still work without recording (the
  transcript is an operator choice); assert the composition forms.
