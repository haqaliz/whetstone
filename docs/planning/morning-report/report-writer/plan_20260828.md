## What the build changed about the spec

**Two corrections, both from integration rather than from reading.**

1. **The record belongs to this night by checkpoint digest, not by run id.** The spec (and the
   brief before it) said to compare `run_id`. A promotion record's `run_id` is the *gate
   evaluation's* operator-declared name — `gate-001` — so the comparison would have been between
   two unrelated strings, passing or failing for no reason. The link that exists is the
   checkpoint: a record concerns this night iff the night's checkpoint digest is one of the two
   the gate compared. Stronger than the spec's version, because a digest is evidence and a name
   is a string somebody typed. A control test covers the night being the **incumbent**, which
   every morning report after the second night will be.

2. **The blanket "`PASS` appears nowhere" assertion was wrong** and was narrowed to the gate's
   own section. The night's `valid_split` legitimately quotes the ledger's own sentence, which
   contains *"strict-PASS set below floor"*; refusing that would have meant paraphrasing a
   sentence the night wrote about itself. The property that matters — no `PASS` rendered as this
   evaluation's verdict — is what is now asserted.
