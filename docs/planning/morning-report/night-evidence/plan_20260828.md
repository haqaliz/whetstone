### Placement decision (state it, don't assume it)

The typed reader could live in `ledger.py` beside `ledger.read`. It goes in the new
`morning.py` instead: nothing but the morning report needs it today, and this tree earns
abstractions on the second implementation rather than designing for the first. `morning.py`
imports `ledger.read`, `LEDGER_SCHEMA` and `LedgerUnreadable` **by identity** so there is one
schema check in the tree, not two. If a second consumer appears, moving it to `ledger.py` is a
pure lift.

## Phase 1 — the typed document and its fail-closed reader

**Goal:** a ledger on disk becomes a `LedgerDocument`, or is refused by name, field by field.

**Prerequisites:** none.

**Files:** `src/whetstone/loop/morning.py`, `tests/loop/test_morning_evidence.py`.

**RED first, in this order** (each watched failing before any production line):

1. `test_a_well_formed_ledger_reads_field_for_field` (AC 1) — build the fixture by calling
   `ledger.write` with a real `Ledger`, **never by hand-typing JSON**: a hand-typed fixture tests
   the reader against a document the writer would never produce, and the two drift silently.
2. `test_every_declared_field_is_required` (AC 2) — parameterised over
   `dataclasses.fields(LedgerDocument)`, deleting each key from the written payload in turn and
   asserting a refusal naming the file **and** that field. This is the anti-staleness assertion:
   a field added later without a refusal fails here rather than defaulting.
3. `test_a_boolean_is_not_an_integer` (AC 3) — `draws: true` is refused. `bool` is an `int`
   subclass, so `isinstance(x, int)` accepts it; the check must be explicit.
4. `test_an_unknown_top_level_field_is_refused` (AC 4), naming it.
5. `test_the_schema_check_is_the_ledgers_own` (AC 5) — a foreign-schema document is refused, and
   the refusal is `LedgerUnreadable` **asserted `is`** against `ledger.LedgerUnreadable`.
6. `test_recorded_on_must_be_an_iso_date` — the spec's own open question, promoted to a test.
   `recorded_on` is a free string; the resolver compares two of them lexicographically, which is
   correct **only** for ISO-8601. Anything else is refused at read time rather than compared and
   silently mis-ordered.
7. `test_the_reader_imports_no_inference_library` (AC 11) — the module's own AST walk, on the
   `preanalysis.py` / `retry.py` precedent (no `mlx`, no `run`, no `scoring`).

**GREEN:** `LedgerDocument` (frozen dataclass) + `read_ledger(path)`. Refusal helpers in the
`gate.read_promotion_record` shape (`gate.py:919-1000`): read → object → schema → unknown fields →
per-field type checks, each raising with the file path and the field name.

**Validation:** `uv run pytest tests/loop/test_morning_evidence.py -q` green;
`uv run ruff check . && uv run mypy src/` clean; full suite green.

**Commit:** `Read a night's ledger fail-closed, field by field (TDD)`

## Phase 2 — resolving "last night", and the refusals that are the feature

**Goal:** `resolve_last_night(runs_root)` answers, or refuses in a way the operator can act on.

**Prerequisites:** Phase 1.

**RED first:**

1. `test_the_greatest_declared_recorded_on_wins` (AC 6) — **three nights whose directory order,
   alphabetical run-id order, and mtime order each disagree with the answer.** Construct the
   mtimes explicitly with `os.utime`. Without this the test passes under an mtime implementation
   and proves nothing; it is the single most important fixture in the aspect.
2. `test_a_tie_is_refused_and_names_the_escape` (AC 7) — two nights on the same greatest
   `recorded_on` raise `AmbiguousNight`, naming **both** run ids and `--run`. A correct refusal
   with no next step leaves the operator stuck.
3. `test_the_tie_refusal_is_watched_failing_against_a_credulous_resolver` (AC 7 control) — a
   deliberately credulous resolver that breaks the tie by sort order is asserted to return an
   answer where the shipped one refuses. This is the implementation this would decay into, and
   the differential is what makes the refusal worth its lines.
4. `test_an_empty_runs_root_is_refused` (AC 8) — `NoRuns`. Never an empty morning.
5. `test_a_corrupt_night_refuses_the_whole_scan` (AC 9) — a run directory with **no** ledger, one
   with a truncated ledger, and one with a foreign schema, each planted **beside two healthy
   nights**; the scan refuses rather than returning the healthy pair. Skipping would make a
   killed night invisible to the one command whose job is to say what happened last night.
6. `test_a_named_run_whose_ledger_disagrees_with_its_directory_is_refused` (AC 10), naming both.

**GREEN:** `resolve_last_night(runs_root)`, `load_named_run(path)`, and the exception classes
`NoRuns` and `AmbiguousNight`.

**Validation:** as Phase 1, plus the full suite.

**Commit:** `Resolve last night by the declared date, refusing every ambiguity (TDD)`

## Testing strategy

Every acceptance criterion in the spec maps to a named test above (ACs 1–11, none dropped).
Fixtures are produced **through `ledger.write`**, so the reader is always tested against the
document the writer actually produces. Deterministic, no network, no model call, no clock: the
only time-shaped value is `recorded_on`, which is a declared input.

**Adversarial coverage.** This aspect does not touch the reward, so the reward-hacking corpus is
not extended. The two adversarial-shaped tests are the ones that matter here and both are
watched failing first: the credulous tie-breaking resolver (Phase 2 #3), and the ordering fixture
whose mtime deliberately contradicts the answer (Phase 2 #1). The failure this aspect actually
prevents is a report that confidently names the wrong night, and those are the two tests that
would catch it.

## Environment, determinism & locality

Nothing leaves the box; nothing is published; no `reports/` directory is touched by this aspect.
No held-out data is read, so there is no train/held-out boundary to cross here — the reader sees
counts and digests, never task contents. The module is pure: same directory tree in, same
document out, with no dependence on wall clock, locale, or hash seed.

## Edge cases and what each produces

| Case | Outcome |
|---|---|
| Runs root does not exist / is empty | `NoRuns`, refused |
| A run directory with no `ledger.json` | Refused during the scan, named — never skipped |
| A ledger that is truncated or foreign-schema | `LedgerUnreadable`, refused |
| Two nights tied on the greatest `recorded_on` | `AmbiguousNight`, naming both and `--run` |
| `recorded_on` not ISO-8601 | Refused at read time, before any comparison |
| `--run` names a directory whose ledger declares another `run_id` | Refused, naming both |
| A field present but of the wrong type (incl. `bool` for an int) | Refused, naming the field |

There is no `UNVERIFIED` outcome in this aspect and there should not be: it reads documents
rather than running anything, so it either answers or refuses. (`check-leakage`'s own argument,
`cli.py:828-832`.)
