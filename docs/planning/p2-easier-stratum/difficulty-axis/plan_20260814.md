## Edge cases / error handling

- **Multi-file gold patches are the norm, not the corner**: the mined fixture's fixing commit
  touches `calc.py` **and** `README.md` (2 non-test files), so the default fixture is already
  out of band on the files axis — band tests need a dedicated single-file fixture, and the
  corpus test's cross-assertion exercises the multi-file shape on real data.
- **Binary hunks** (`--binary` on, `derive.py:201-202`): `GIT binary patch` payload lines begin
  with a digit, never `+`/`-`; the walk must not count them. Fixture + corpus cross-assert.
- **`\ No newline at end of file` marker lines** are annotations, not content: never counted
  (numstat agrees).
- **Renames**: `changed_paths` keeps both halves (`sources.py:512-515`), so files counts both;
  numstat reports the destination only (`repo.py:93-95`) — the cross-assertion is lines-only,
  stated in the test's docstring.
- **Source-A-shaped task** (no `commit`/`parent`): refusal by name, never measured, never in the
  band (spec D8).
- **Empty gold patch**: refused as "nothing to measure" even though `changed_paths` already
  refuses the no-non-test-path case (`sources.py:277-286`) — belt and braces.
- **Git failures** (`GitFailed`, `SubprocessError`, `OSError`): refusal with a reason naming
  task and exception (`control.py:242-252`); the corpus test asserts every refusal has a
  non-empty reason and the document records them.
- **The recomputation test in CI skips** — a named, documented skip, never a silent one; the
  sandbox-CI precedent treats skips as markers to be read (`ci.yml:51-75`).
- **A rule edit between phases**: any edit to the rule functions or band constants changes
  `rule_digest()` and refuses the committed document — regenerate the document in the same
  commit (spec: open risk).
