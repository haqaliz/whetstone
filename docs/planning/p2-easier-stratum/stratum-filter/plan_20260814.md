## Edge cases / error handling

- An unreadable or non-JSON stratum file: `StratumSchemaError`, never a traceback, and
  never a default — the loader is fail-closed like `load_task` (`task.py:165-177`).
- A membership id duplicated, or `values` keys ≠ membership: refused by name (spec D4-4) —
  a document that cannot be read as the set it claims is not a document this run trusts.
- Membership order vs load order: `include_stratum` returns load order (spec D5), so two
  runs agree and the contract SHA does not depend on the document's list order.
- A stratum that narrows nothing the run could observe: the run-side refusals are empty
  membership and empty-after-overlay only; the identical-to-the-declared-set degeneracy is
  aspect 1's (spec Open questions 4). Do not add a run-side widening check.
- `--stratum` under `--probe`: allowed — the probe slices the filtered set; a probe is a
  timing sample over the tasks that would be scored, which is the question it exists to
  answer.
- Dev ∩ stratum overlap: exclusion (spec D7), never a refusal — the real probe's 5 declared
  dev ids may fall inside the band. A later editor "fixing" this into a refusal breaks M4.
