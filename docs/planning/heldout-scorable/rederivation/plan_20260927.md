## Testing strategy

- Unit tests mapped to phases; written first. The adversarial angle is the verification
  itself: the apply step must refuse a staged re-mint that is NOT provably identical (a
  changed sha12, a missing manifest, a foreign file), and must refuse to double-apply — a
  silent corpus change would make the amendment's "provably identical commit set" claim
  false.
- Determinism: every derivation is over immutable git objects and declared seeds; re-running
  the apply from the snapshot yields the same committed documents.
- Commands: per-phase `uv run pytest <path> -q`; final `uv run pytest tests/loop/ tests/tasks/ -q`,
  `uv run ruff check .`, `uv run mypy src/`.

## Environment, determinism & locality

Machine-level state (the primary's `tasks/local/` and `_sandbox/remint/`) — never copied
into a worktree, always addressed by absolute path. The snapshot restores the pre-swap
corpus. Nothing leaves the box; no network; no live model.

## Edge cases & error handling

- Double-apply → named refusal (AC10).
- Staged re-mint mismatch (count, ids, sha12s) → named refusal before any file moves (AC3).
- A manifest whose `repo_url` rewrite target is missing → named refusal (the declared donor
  paths must exist).
- Stratum re-derivation refuses if a task's donor cannot be read (its own fail-closed
  loader) — reported, never guessed.
- Heldout re-derivation: an unreadable donor is `HeldoutUnscorable` (aspect 2) — the sheet
  halts by name.
