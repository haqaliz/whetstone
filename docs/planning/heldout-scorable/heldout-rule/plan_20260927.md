## Testing strategy

- Unit tests mapped to phases; written first.
- The adversarial angle for a selection rule: the differential is inherited from aspect 1
  (excluded == bakeoff's own refusal set); this aspect's own adversarial pins are the
  consistency refusals (AC6) — a doctored document that smuggles an excluded id into the
  membership, or an excluded entry that blurs into `refusals`, must refuse by name.
- Determinism: recomputation pin byte-for-byte (AC9); no network; no clock.
- Commands: per-phase `uv run pytest <path> -q`; final `uv run pytest tests/loop/ -q`,
  `uv run ruff check .`, `uv run mypy src/`.

## Environment, determinism & locality

The regeneration reads the machine corpus (primary checkout's `tasks/local/`) and the
donors (aspect 1's `oracle_fittable` needs them) — operator's machine, CI skips. Nothing
leaves the box. The document is evidence about the data, never the data (counts and ids
only — the locality walk test stays green).

## Edge cases & error handling

- Unfittable member in a band → excluded, band draws fewer; floors are the binding
  statement (unmet → `EmptyHeldout`, the published finding).
- Unreadable donor at derivation time → named refusal of the derivation (AC7), never an
  exclusion.
- A stale committed document under the new loader → named refusal; a gate pointed at it
  halts with exit 2 (the existing gate refusal path) — this is desired, not a bug.
- `excluded` ids stay in `corpus`/`difficulty`/`bands` — the loader's set-consistency
  checks (`set(bands) == measured_ids`, `difficulty ∪ refusals == corpus`) must still hold.
