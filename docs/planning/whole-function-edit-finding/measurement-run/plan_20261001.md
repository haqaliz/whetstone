### Phase 3 — the offline instrument

- **Goal:** `src/whetstone/bakeoff/resolvability.py` — stdlib-only, deterministic, no model,
  on the `addressability.py` boundary, executing the spec's § Classes, § Decision and §
  Sub-counts.
- **Prerequisites:** Phase 1 (the parser), Phase 2 (the run's artifacts).
- **Files to create:**
  - `src/whetstone/bakeoff/resolvability.py` — `SCHEMA = "whetstone-resolvability/1"`;
    the `RULE` constant `"GO iff count(RESOLVABLE) * 2 > population"` cross-pinned into every
    output document; the worst-first ladder `UNCLASSIFIED > MALFORMED > NO_FILE > AMBIGUOUS >
    UNKNOWN_FUNCTION > NOT_PARSEABLE > RESOLVABLE`; `decide()` (strict majority; empty
    population refused, never decided); the resolution logic (materialize a **read-only**
    checkout at `base_commit` — the locatability pattern — `ast.parse` the named file, find
    module-level `FunctionDef`/`AsyncFunctionDef` by exact name, compute the extent
    including decorators and signature); the wrapped-parse gate
    (`ast.parse("def __whetstone_synthetic():\n" + body)` — `IndentationError` → `MALFORMED`,
    any other parse failure → `NOT_PARSEABLE`); the sub-counts (splice_in_context:
    re-parse the file with the body spliced over the extent; outside_shown_set: real path
    outside the shown set, held-test paths included) reported beside and never decisive; the
    named refusals (manifest/transcript unreadable, wrong schema, missing fields, empty task
    list, task-set mismatch vs the pinned 16 by identity, digest disagreement with the
    manifest's recorded document digests, `prompt_sha256` disagreement between manifest and
    transcript — "not this run's evidence"); exit 0 GO / 1 NO-GO / 2 refusal with refusals
    writing nothing; `UNCLASSIFIED` (including the `NO_ORACLE` members) stays in the
    denominator.
  - `tests/bakeoff/test_resolvability.py` + fixtures — RED first: one fixture per class
    asserting the class and its place in the worst-first ladder (a completion that is both
    `MALFORMED` and `NOT_PARSEABLE` resolves to `MALFORMED`); a RESOLVABLE fixture (unique
    module-level function, parseable body) resolving RESOLVABLE with splice_in_context 1; a
    fixture that would score RESOLVABLE under a **weaker** rule — a name matched loosely
    (substring, or a method name) — scoring `UNKNOWN_FUNCTION`/`AMBIGUOUS` here; a body at
    column 0 scoring `MALFORMED` (the indentation class rule); an `IndentationError`-vs-
    `SyntaxError` pair; the decision inequality (a population of 3 with 1 RESOLVABLE is
    NO-GO, with 2 is GO — the exact-half boundary); the rule sentence cross-pinned into the
    output document; refusals (wrong task set, digest mismatch, `prompt_sha256`
    disagreement, empty population) exiting 2 and writing nothing; `UNCLASSIFIED` in the
    denominator (a population with one unclassifiable member can still GO).
  - Fixture tasks: mirror the addressability test fixtures' mechanism (a fixture corpus root
    of flat fixture repos with functions — `calc.py`-shaped, the cheat-fixture precedent).
- **Validation:** `uv run pytest tests/bakeoff/test_resolvability.py -q` green.

## 4. Testing strategy

- **Written first, always** (RED before GREEN); per-phase modules listed above.
- **Deterministic and offline**: fixed fixture tasks, no wall-clock dependence, no network;
  the instrument never calls a model — fixture transcripts/manifests only. The only real
  model involvement is the operator's Phase 5 run, commanded by the runbook.
- **The weaker-check differential** (the measurement's adversarial shape): the suite asserts
  that completions a **looser** instrument would score RESOLVABLE — a function name matched
  loosely or by substring, a method name, a body spliced with repair, a body at column 0 —
  score worse here (`UNKNOWN_FUNCTION`, `AMBIGUOUS`, `MALFORMED`), and that the decision
  function is blind to the sub-counts by construction (a fixture where splice-in-context is
  0 while RESOLVABLE is 2/3 still decides GO — the sub-count is reported beside, never
  decisive).
- **Hygiene (AC10)**: `tests/test_no_inference_on_reward_path.py`,
  `tests/test_reward_path_scope_is_partitioned.py`, the one-way import test, and
  `tests/bakeoff/reward_amendments.py` stay green — nothing under `verify/`/`tasks/`
  changed. The renderer/instrument modules import no inference library (asserted in Phase 1).
- **Commands**: `uv run pytest tests/bakeoff/ -q` after each phase; `uv run pytest -q` +
  `uv run ruff check .` + `uv run mypy src/` at checkpoints.

## 5. Environment, determinism & locality

- **Weights**: `weights/` is machine-level and gitignored; the run references the primary
  checkout's copy by **absolute path** — never fetched inside the worktree; re-verified by
  sha256 (the runbook's preflight); the pinned revision
  `d1e3b690c8e225d7795bccddf971ca6be68b2012` (§ 10.10).
- **GPU**: machine-level; one MLX process at a time (serialized in the runbook).
- **No network**: `mlx_engine` sets `HF_HUB_OFFLINE=1` (the existing behavior, unchanged).
- **Evidence**: counts live only in gitignored `runs/whole-function-edit-finding/`
  (`.gitignore:20`); no count is committed; the finding points at the runs directory.
- **The held-out boundary**: the population excludes the three held-out overlap members by
  identity; the instrument refuses a task set that differs from the pinned 16 and refuses
  document digests that disagree with the manifest's recorded digests — a held-out member
  can never be a rollout target, and a re-derived split can never be silently consumed.
- **Nothing leaves the box**: the run, the evidence, the finding — all local.

## 6. Edge cases & error handling

- **Refusals exit 2 and write nothing** (spec AC4): relative `--workspace`; empty /
  mismatched / unknown-member population; not-one-candidate (weights naming more than the
  pinned 32B); control fold not `INTACT`; provenance unreadable; weights unverified; the
  six stratum/heldout loader errors; manifest/transcript unreadable or wrong schema; missing
  manifest fields; digest disagreement; `prompt_sha256` disagreement between manifest and
  transcript ("not this run's evidence").
- **`NO_ORACLE` members**: no prompt rendered, `UNCLASSIFIED`, in the denominator — the rule
  claims no scorable filter (spec R5).
- **Class edges**: `IndentationError` → `MALFORMED`, any other wrapped-parse failure →
  `NOT_PARSEABLE`; an empty body fails the wrapped parse (expected indented block) →
  `MALFORMED`; a non-UTF-8 file or an unmaterialisable checkout → `UNCLASSIFIED`.
- **Killed run**: delete and recreate the workspace, re-run the same command unchanged
  (fresh run id from the declared `--recorded-on`).
- **Timing**: generation bound from committed metadata; halt at roughly twice the bound.
- **The `UNVERIFIED` contract**: the measurement rows are `UNVERIFIED` by design and the
  instrument's classes are never graded — nothing in this unit can be mistaken for a win.

## 7. Agent execution notes

- **Strict TDD per phase** (RED → GREEN → REFACTOR); a phase's failing tests come first,
  and a phase is not done until its tests and the full `tests/bakeoff/` suite pass.
- **Checkpoints for human review**: after Phase 4 (before any GPU spend — the run is the

  differs from `:355` as cited), stop and surface it rather than improvising — the
  precedent modules are the template.
- **Commit discipline**: one commit per phase, messages as suggested; the branch stays
  green; no commit of anything under `runs/` or `weights/`.
