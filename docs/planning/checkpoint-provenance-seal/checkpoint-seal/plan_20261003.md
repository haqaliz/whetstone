### Phase 1 — Canonical claims

- **Goal:** the pure helpers the seal is built from, with their bytes pinned.
- **Prerequisites:** none.
- **Files:** `tests/loop/test_checkpoint_seal.py` (new), `src/whetstone/loop/sft.py`.
- **Add to `sft.py`:**
  - `CHECKPOINT_SCHEMA_V1 = "whetstone-checkpoint/1"` and `CHECKPOINT_SCHEMA_V2 =
    "whetstone-checkpoint/2"`; `CHECKPOINT_SCHEMA = CHECKPOINT_SCHEMA_V2` (the schema now written).
    Add all three to `__all__`.
  - `_UNSEALED_KEYS = frozenset({"schema", "digest", "claims"})`.
  - `_canonical(value: Any) -> bytes`: `json.dumps(json.loads(json.dumps(value)), sort_keys=True,
    separators=(",", ":"), ensure_ascii=True).encode("ascii")`. The inner round trip is
    requirement 11: the hashed value is what a reader will parse back, never the in-memory object.
  - `_claim_hashes(body: Mapping[str, Any]) -> dict[str, str]`: `{key: sha256(_canonical(value))}`
    for every key of `body`. `body` never contains `_UNSEALED_KEYS`; assert this and raise
    `CheckpointUnverified` if it does (a writer bug, not an operator error).
  - `_claims_digest(claims: Mapping[str, str]) -> str`: sha256 over `"\n".join(f"{key}:{hash}")`
    in sorted key order, UTF-8.
- **Failing tests first (criteria 6, 10):** a fixed mapping hashes to a fixed hex string literal
  pinned in the test (compute it once, paste the literal, never recompute in the test); a body
  holding int, float, `None`, nested mapping, list and tuple has the same claim hash as its
  `json.loads(json.dumps(...))` form; key order of the input does not change the hash;
  `_claim_hashes` refuses a body containing `digest`.
- **Validation:** `uv run pytest tests/loop/test_checkpoint_seal.py -q`.
- **Commit:** `checkpoint-seal: canonical claim hashes, their bytes pinned (TDD)`.

### Phase 2 — Write v2, verify both schemas

- **Goal:** `write_checkpoint` writes v2; `verify_checkpoint` accepts v1 and v2 and returns the
  verified claims.
- **Prerequisites:** Phase 1.
- **Files:** `tests/loop/test_checkpoint_seal.py`, `src/whetstone/loop/sft.py`.
- **`Checkpoint` gains defaulted fields** (existing constructors untouched):
  `base_repo_id: str | None = None`, `base_revision: str | None = None`,
  `dataset_digest: Any = None` (the value **as recorded, unvalidated**; the gate keeps its shape
  check, which is why the type is `Any`), `sealed: bool = False`. Docstring each; `sealed` says
  "`True` only for a v2 checkpoint whose every claim re-hashed; a v1 checkpoint is never sealed".
- **`write_checkpoint`:** build `body` exactly as today's document minus `schema` and `digest`
  (`base`, `dataset_digest`, `run_seed`, `backend`, `training_args`, `tool_versions`, `validation`,
  `capacity_probe`, `files`); `claims = _claim_hashes(body)`; `digest = _claims_digest(claims)`;
  write `{"schema": V2, "digest": digest, "claims": claims, **body}` with the existing
  `indent=2, sort_keys=True`. Return `Checkpoint(...)` with the new fields filled and
  `sealed=True`. The file hashing, the adapter-config merge and the empty-directory refusal above
  it are **not touched**.
- **`verify_checkpoint`:** parse the document **once**.
  1. Schema must be V1 or V2, else the existing "does not declare schema" refusal, now naming both.
  2. **V2 only, before anything else is trusted:** `claims` must be a mapping of str to str. The
     body keys are the document's keys minus `_UNSEALED_KEYS`. Refuse, naming the key: a body key
     with no claim (`"… carries {key!r}, which no claim seals"`); a claim with no body key; a body
     key whose recomputed hash differs from its claim (`"claim {key!r} … the document's {key!r}
     was changed after the checkpoint was sealed"`). Then refuse if `_claims_digest(claims)` differs
     from `raw["digest"]`.
  3. Parse `files`, run the existing per-file existence/size/sha256 loop, and the existing
     `untrained`/empty-files contradictions. For **V2** do not run the old `_digest_of(recorded)`
     comparison (the digest no longer reduces from files alone — `files` is sealed as a claim). For
     **V1** keep it exactly as written.
  4. Return `Checkpoint` with `base_repo_id`, `base_revision` from `raw["base"]` when it is a
     mapping (else `None`), `dataset_digest=raw.get("dataset_digest")`, `sealed = (schema == V2)`.
     A V1 document that also carries a `claims` key is read as V1: the key is ignored and
     `sealed` stays `False` (criterion 5).
- **Failing tests first (criteria 1, 2, 3 a–d, 4, 5, 9, 10):** round trip returns `sealed=True` and
  an equal `digest`; for each of `dataset_digest`, `base.repo_id`, `base.revision`, `backend`,
  `run_seed`, `training_args`: edit it in the written JSON, leave `digest` and `claims`, assert
  `CheckpointUnverified` whose message contains the key name; the adversarial set — (a) added
  unlisted top-level key, (b) a key and its claim both deleted with `digest` unchanged, (c) two
  claims' hashes swapped, (d) schema rewritten to V1 (assert it fails and that the file-only seal
  would have accepted the same edit: build the v1 doc by hand with the same edited
  `dataset_digest` and assert it **verifies** — this is the "passes under the weaker check"
  half); v1 portability-arm-shaped fixture verifies with `sealed=False` and populated
  `dataset_digest`/base; v1 doc with a `claims` key is `sealed=False`; a V2 document handed to a
  verifier that only knows V1 is refused (assert via a local copy of the old equality check).
- **Validation:** `uv run pytest tests/loop/test_checkpoint_seal.py tests/loop/test_sft.py
  tests/loop/test_adapter_artifact.py tests/loop/test_adapter_vocabulary.py -q`; then the full
  suite — expect the known deliberate failures listed in Phase 4 and nothing else.
- **Commit:** `checkpoint-seal: write whetstone-checkpoint/2, verify both, return the claims (TDD)`.

## 4. Testing strategy

- **Unit tests** are the phase lists above; they are written first.
- **Adversarial (mandatory — this touches the gate's input trust):** the six cheats in PRD § 6, each
  asserted to fail under V2 *and* to pass under the file-only seal, so the test proves the new check
  is doing the work. The cheat "rewrite claims and digest together" is asserted to **succeed** in a
  test named for what it documents (`test_a_forger_who_recomputes_the_digest_is_not_caught`), so the
  limit in PRD § 3 is executable rather than only prose.
- **Integration:** the full suite; `tests/loop/test_gate*.py` exercise `verify_checkpoint` through
  the gate and must stay green with no edit beyond `_record_backend`.
- **Manual:** none. No GPU, no network, no real checkpoint is read.
- **Deterministic:** fixed strings and tmp directories; no clock, no randomness.

## 5. Environment, determinism, locality

- No environment variables. No model call, no weights, no network, no GPU.
- **Train/held-out boundary:** this aspect reads and writes checkpoint documents only. It never
  reads a held-out document or a task. Nothing from the held-out set can reach training through it.
- Nothing leaves the machine.
- Determinism: the canonical bytes are pinned by a literal; a library or Python-version change that
  moved them would fail Phase 1's test rather than silently re-digest every checkpoint.

## 6. Edge cases and error handling

| Case | Outcome |
|---|---|
| V2 claim hash differs | `CheckpointUnverified`, names the key |
| Body key with no claim / claim with no key | `CheckpointUnverified`, names the key |
| `claims` missing or not a str→str mapping on a V2 document | `CheckpointUnverified` |
| Digest does not reduce from `claims` | `CheckpointUnverified` |
| V2 schema string rewritten to V1 | `CheckpointUnverified` (v1 digest check fails) |
| V1 document with a `claims` key | verifies as V1, `sealed=False` |
| Unknown schema | `CheckpointUnverified`, names V1 and V2 |
| `base` not a mapping | `Checkpoint.base_*` are `None`; the gate refuses where it needs them (aspect 2) |
| Value that does not survive a JSON round trip | hashed from the round-tripped form; a non-serialisable value raises at write time, before anything is written |

Every failure's default is *don't accept*; none returns a Checkpoint with `sealed=True`.
