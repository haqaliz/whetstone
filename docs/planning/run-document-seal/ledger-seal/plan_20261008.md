### Phase 1 — `whetstone-run/3`: the body seals, the reader verifies, `/2` reads unsealed

- **Goal:** `ledger.document` emits a sealed `whetstone-run/3`; `read` verifies it and is the only
  read path; a `/2` document reads unsealed behind the downgrade guard; `/1` and anything else stay
  refused; every tamper shape is a named `LedgerUnverified`.
- **Prerequisites:** `seal-core` Phase 1.
- **Files:** `tests/loop/test_ledger_seal.py` (new), `src/whetstone/loop/ledger.py`.
- **Add to `ledger.py`:**
  - Constants beside the current one (`:49-53`): `LEDGER_SCHEMA_V1 = "whetstone-run/1"` (declared
    only, still refused), `LEDGER_SCHEMA_V2 = "whetstone-run/2"`, `LEDGER_SCHEMA_V3 =
    "whetstone-run/3"`; `LEDGER_SCHEMA = LEDGER_SCHEMA_V3`. Add all to `__all__`. The two
    comments above `LEDGER_SCHEMA` move with the behaviour.
  - `_body(ledger: Ledger) -> dict[str, Any]`: today's `_payload` minus `schema` — the fifteen
    keys `run_id`, `recorded_on`, `run_seed`, `draws`, `model`, `backend`,
    `generation_contract`, `task_set`, `environment_pins`, `tool_versions`, `seeds`,

    name. `_draw` is untouched; the `journal.py` codec rule stands (a `Ledger` field not named in

    v3. `night.run_night` (`night.py:392`) and the write-even-when-training-raises path need no
    edit.
  - `class LedgerUnverified(LedgerUnreadable)`: the named refusal for every malformed or tampered
    sealed shape. Subclassing `LedgerUnreadable` (`:65-66`) is deliberate — every consumer's
    refusal tuple already holds the base class (`check_probe.py:84-90`, `check_leakage.py:145`,
    `morning.py:787-796`, `honest_report.py:118`), so no tuple edit is needed.

    guard below.

    refused as `LedgerUnverified`, because no `/2` writer ever emitted either. A `/2` ledger has no
    file-digest self-consistency fallback (unlike `sft.py:915-916, :983-989`), so the guard must be
    explicit or a re-labelled v3 document reads as unsealed with no refusal anywhere.
  - `read(path) -> Mapping[str, Any]` stays public as `verify_document(path).document`, so the
    verifying path is the only path and no consumer's call site changes; its docstring (`:257`) and
    the `LEDGER_SCHEMA` comment (`:50-53`) move with the behaviour.

## 4. Testing strategy

- **Unit tests** are the phase lists above; they are written first.
- **Adversarial (mandatory — this touches the gate's ledger-side input trust):** every tamper shape
  in AC 5 refuses by name, and the recompute-everything forger is asserted to **pass** in a test
  named for the limit, so PRD § 3 is executable rather than only prose. The `/2` downgrade guard
  gets its own tests, because a re-labelled v3 document is the one downgrade with no fallback
  check.
- **Integration:** the writer-based suites (`test_run_ledger.py`, `test_check_probe.py`,
  `test_morning_evidence.py`, `test_morning_render.py`) read real documents through the real
  writer and must stay green; `test_night_integration.py`'s byte pins prove the night's output is
  deterministic after the bump.
- **Deterministic across processes:** fresh interpreters under two `PYTHONHASHSEED` values must
  sha256 to the same `ledger.document(_ledger())`; the byte pins at `test_run_ledger.py:204` and
  `test_night_integration.py:326-374` are the in-process half.
- **No GPU, no network, no model.** Tmp directories and fixed inputs only.
- Full-suite run at every phase end; any failure outside the deliberate list is a stop-and-report.

## 5. Environment, determinism, locality

- **No environment variables** are read by the code under test; the cross-process determinism test
  sets `PYTHONHASHSEED` only in its subprocess, as the existing pattern does.
- No model call, no weights, no network, no GPU.
- **Train/held-out boundary:** the ledger records hashes and counts of the selected examples
  (`seeds`, `draws_recorded`, the `dataset` counts and digest) and the held-out record is a digest
  and a membership count, never membership. `ledger.py` never reads a task or a held-out document;
  nothing here can move a held-out member into training.
- Nothing leaves the machine.
- **Determinism:** the seal is a pure function of the payload — field-by-field serialisation,
  canonical JSON after a round trip, sorted claim lines, and the schema tag as domain separation —
  so the same inputs produce byte-identical documents and a v2 and a v3 document cannot collide.

## 6. Edge cases and error handling

| Case | Outcome |
|---|---|
| Any of the fifteen body keys moved | `LedgerUnverified`, names the key |
| Body key with no claim / claim with no key | `LedgerUnverified`, names the key |
| Claim and body key deleted together, digest left | `LedgerUnverified` (digest does not reduce) |
| Two claims' hashes swapped | `LedgerUnverified`, names the first moved key |
| Claim hash not 64 lowercase hex / newline in a claim key | `LedgerUnverified` |
| `claims` missing or not a str→str mapping under `/3` | `LedgerUnverified` |
| `/3` schema rewritten to `/2`, seal keys retained | `LedgerUnverified` (downgrade guard) |
| `/2` carrying `claims` or a top-level `digest` | `LedgerUnverified` (downgrade guard) |
| `/2` payload relabelled `/3` without claims | `LedgerUnverified` |
| `/1`, or any schema but `/2` and `/3` | `LedgerUnreadable`, naming `/2` and `/3` |
| Missing file / malformed JSON | `LedgerUnreadable` |
| A `/2` document | read, `sealed=False`, byte-unchanged |
| A forger who recomputes claims and digest consistently | accepted, `sealed=True` — the documented unkeyed-hash limit, in a named test |
| A v3 ledger handed to an older reader | refused by schema equality (breaking; listed) |
| Every refusal above | exit 2 through the consumers' existing `LedgerUnreadable` tuples; no tuple edit |

Every failure's default is *don't accept*; nothing returns `sealed=True` without re-hashing.
