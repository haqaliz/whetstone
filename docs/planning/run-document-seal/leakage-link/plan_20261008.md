## 4. Testing strategy

- Unit tests are the phase lists; they are written first.
- **Adversarial (mandatory — this is the leak guard the runbook halts on):** every tamper shape
  refuses with exit 2 and nothing reported clean; the refusal fires before the link (a valid
  matching checkpoint cannot turn a tampered dataset into a link); the re-sealed document is refused
  by the link, not the seal, and the test says so; the mixed-generation pair refuses in both
  directions with the two values asserted different first, so the guarantee is a tested property
  and not an accident of two digest computations differing.
- **The honesty rule is executable:** `test_no_link_line_claims_verification` runs over the four
  generation pairs and asserts neither line contains "verified"; "sealed" always travels with a
  generation tag, and the tamper-evidence-not-authentication limit is stated in the sealed cases.
- **Unchanged-behaviour:** the existing CLI suite passes with only the named literal edits; the
  exit codes and stdout/stderr routing are untouched; `tests/test_gate_leakage_finding.py` passes
  unedited (or skips loudly); the gate suite, the reward and everything under `verify/`/`tasks/`
  are not read and not touched.
- No GPU, no network, no weights, no model call; tmp dirs and fixed inputs only.
- Deterministic: the pinned tuple is pasted once; no clock, no randomness; every line is a pure
  function of the report.
- Full-suite run at every phase end; any failure outside the deliberate list is a stop-and-report.

## 5. Environment, determinism, locality

- No environment variable set or read by this aspect. No model call, no network, no GPU.
- **Train/held-out boundary:** this aspect exists to protect that boundary. It reads held-out
  documents only to compare their membership, never writes one, and touches nothing under `tasks/`.
  The reward is untouched; `UNVERIFIED` is never a win; a seal state alone changes no verdict and
  no exit code.
- Nothing leaves the machine. The only documents read are the run's `dataset.json`, the
  checkpoint's `provenance.json` and the held-out document; the only write is a test fixture's tmp
  directory.
- Determinism: disclosure is a pure function of the report/night; the byte pin is a pasted literal;
  the schema tag is part of the digest's material, so a v1 and a v2 value cannot collide.

## 6. Edge cases and error handling

| Case | Outcome |
|---|---|
| v2 payload field moved (`denominator`, `unverified`, `coverage`, `examples`) | `dataset.DatasetUnverified`, names the key; exit 2; nothing on stdout; fires with and without `--checkpoint`, before `_link_of` and `check_overlap` |
| v2 document re-sealed after the checkpoint recorded the old digest | the document verifies; the link refuses: `CheckpointNotThisRun`, exit 2 |
| v1 checkpoint ↔ v2 document | `CheckpointNotThisRun` (the two generations' digest values differ), exit 2 |
| v2 checkpoint ↔ v1 document | `CheckpointNotThisRun`, exit 2 |
| v2 document with `digest` popped | `DatasetUnverified` (a seal refusal), exit 2 |
| schema not V1/V2 | `DatasetUnreadable` (the reader's `ValueError` wrapped exactly as today), exit 2 |
| v1 run document, matching checkpoint | reads unsealed; run link line names `whetstone-training-set/1` recorded, not sealed |
| v1 checkpoint + v1 run | two-line block, both sides recorded, never "verified" |
| v2 checkpoint + v2 run | two-line block, both sides sealed, never "verified" |
| no `--checkpoint` | no link lines; disclosure byte-identical to today; a tampered v2 still refuses |
| any verdict | exit codes 0/1/2 and stdout/stderr routing unchanged; seal state alone never changes a verdict |

Every failure's default is *don't accept*; nothing is reported clean when the dataset could not be
verified, and no link line is emitted for a document that was not read.
