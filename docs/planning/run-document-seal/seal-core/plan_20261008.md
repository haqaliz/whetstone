## 2. Implementation phases

Every phase is RED → GREEN → REFACTOR. No production line before its failing test. Phase 1's first
task is a characterization pin, which is green by construction on the current tree — its value is
that it can only go red if the extraction moves a byte.

### Phase 1 — Extract `seal.py`; the checkpoint's bytes do not move

- **Goal:** one stdlib-only home for canonical bytes, claim hashes, the domain-separated claims
  digest and claim verification; `sft.py` delegates; no checkpoint byte or message changes.
- **Prerequisites:** none.
- **Files:** `tests/loop/test_seal.py` (new), `src/whetstone/loop/seal.py` (new),
  `src/whetstone/loop/sft.py`.
- **Tasks, in order:**
  1. **Characterization (write first, against the current code, never edit again in this unit):**
     build the standard checkpoint fixture (the one the seal tests already use), write it, and
     assert the sha256 of `provenance.json`'s bytes equals a literal computed once and pasted. Run
     it now — it must pass before the extraction starts.
  2. **RED:** `tests/loop/test_seal.py` for the module API: `canonical` of a fixed mapping equals a
     pinned byte literal (the same value the checkpoint tests pin); a tuple hashes as its
     round-tripped list; `claims_digest` for a fixed claims map is a pinned literal and two schema
     tags give two different digests for the same claims (domain separation); `claim_hashes`
     refuses a body containing an unsealed key and a newline-bearing key, raising the passed
     `refuse` type and naming the `subject`; `verify_claims` names the moved key, the unclaimed
     key, the orphaned claim, and a digest that does not reduce; with `subject="checkpoint"` its
     messages equal the current `_verify_claims` messages byte-for-byte (assert the exact strings
     for at least the moved-key and digest-mismatch cases).
  3. **GREEN:** create `seal.py` with the API above; in `sft.py`, replace the moved bodies with
     delegation (import the pieces under their existing private names or call them directly — the
     rest of `sft.py` does not change). `_UNSEALED_KEYS` and `_CLAIM_HASH` become aliases imported
     from `seal`.
  4. **REFACTOR:** move the docstrings with the code; the domain-separation reasoning
     (`sft.py:189-202`) moves to `claims_digest`; the checkpoint vocabulary stays in the
     checkpoints' delegation (subject/refuse arguments).
- **Validation:** `uv run pytest tests/loop/test_checkpoint_seal.py tests/loop/test_seal.py
  tests/loop/test_baseline_checkpoint.py -q` — the checkpoint suite **unedited** — then
  `uv run ruff check . && uv run ruff format --check . && uv run mypy`.

## 4. Testing strategy

- Unit tests are the phase lists; written first. Adversarial cases are mandatory — this is the
  dataset half of the gate's input trust: every edit shape refuses by name, and the
  recompute-everything forger is asserted to pass in a test named for the limit
  (`test_a_forger_who_recomputes_the_claims_is_not_caught`), so PRD § 3 is executable.
- Integration: `tests/loop/test_night.py` and `test_night_integration.py` write real documents
  through the real writer and must stay green (determinism byte pins);
  `tests/test_gate_leakage_finding.py` reads the real v1 night-001 dataset through
  `check-leakage` and must pass unedited.
- No GPU, no network, no weights; tmp dirs and fixed inputs only.
- Full-suite run at every phase end; any failure outside the deliberate list is a stop-and-report.

## 5. Environment, determinism, locality

- No environment variables, no model call, no network, no GPU. `seal.py` imports stdlib only;
  `tests/test_no_inference_on_reward_path.py` and `tests/test_reward_path_scope_is_partitioned.py`
  stay green.
- **Train/held-out boundary:** this aspect reads and writes run documents only. The dataset
  document holds task ids and hashes of selected training examples; this aspect never reads a
  held-out document or a task, and nothing here can move a held-out member into training.
- Nothing leaves the machine.
- Determinism: canonical bytes are pinned by literals; the schema tag is part of the digest's
  material, so a v1 and a v2 document cannot collide; the same inputs produce byte-identical
  documents from `build`/`document` (existing byte pins plus the new ones).

## 6. Edge cases and error handling

| Case | Outcome |
|---|---|
| V2 claim moved | `DatasetUnverified`, names the key |
| Body key with no claim / claim with no key | `DatasetUnverified`, names the key |
| `claims` missing or not str→str on a V2 document | `DatasetUnverified` |
| Digest does not reduce from claims | `DatasetUnverified` |
| Newline key / non-hex hash | `DatasetUnverified` |
| Schema not V1 or V2 | `ValueError` (wrapped by callers as today), names both schemas |
| V1 document | read, `sealed=False`, byte-unchanged |
| V2 schema rewritten to V1 with recomputed v1 digest | reads as unsealed — the documented forger limit, in a named test |
| Direct `Dataset(...)` with a digest that does not match its body | the written document fails verification on read; `build` is the only constructor in `src/` |
| `arm.read_selection` on a tampered v2 | `DatasetUnverified`, CLI exit 2, nothing trained |

Every failure's default is *don't accept*; nothing returns `sealed=True` without re-hashing.
