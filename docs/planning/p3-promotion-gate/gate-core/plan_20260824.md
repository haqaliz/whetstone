**Goal:** given per-task outcome maps for candidate and incumbent over the held-out membership,
exactly one of `promoted` / `rejected` / `UNVERIFIED` per the roadmap rule
(`docs/ROADMAP.md:420-427`).

**Files:**
- `src/whetstone/loop/gate.py` (new) — `decide(candidate: Mapping[str, Outcome], incumbent:
  Mapping[str, Outcome]) -> GateDecision` (a small frozen dataclass carrying the exit, the counts
  `solved_new`, `solved_old`, `regressed`, `unverified` over the shared denominator, and the
  retry/unverified detail). The rule verbatim: `promote iff solved_new > solved_old AND regressed
  == 0 AND unverified == 0`. Uses `Outcome` **by identity** (`whetstone.bakeoff.scoring.Outcome` —
  the same member the loop's `TRAINABLE` imports). No verdict logic is re-decided here; the
  per-task verdict reduction happens before this function (Phase 2), through
  `whetstone.verify.verdict.reduce` imported by identity.
- `tests/loop/test_gate.py` (new) — **written first, watched failing**: known-better →
  `promoted`; known-worse → `rejected`; equal solved counts → `rejected` (the `>` term, never a
  tie-break); candidate == incumbent → `rejected` (asserted test, not an accident); one
  still-unverified task → `UNVERIFIED` (the whole eval reduces; `docs/ROADMAP.md:438-440`); a
  regressed task (incumbent-solved, candidate-unsolved) → `rejected` even with a solved gain.

## Phase 2: Scoring and the promotion record

**Goal:** the gate scores both checkpoints on the held-out membership and records the promotion.

**Files:**
- `src/whetstone/loop/gate.py` — `run_gate(...) -> GateOutcome`:
  1. `verify_checkpoint` both sides **by identity** (`whetstone.loop.sft.verify_checkpoint`,
     sft.py:453) — `CheckpointUnverified` refuses the run naming the checkpoint.
  2. Load the held-out document via aspect 1's loader **by identity**; a held-out set of zero is
     refused by name; load the corpus roots (`--tasks`/`--public`/`--pool` mirrors the night's
     flags) and apply the membership.
  3. Per (side, task): score through the harness — `whetstone.bakeoff.scoring.score` **by
     identity** (scoring.py:357-366) with the side's generator, a `tmp`-style sandbox root,
     `Interpreters(workspace=...)`, `pool` for public tasks; the generator comes from the gate's
     engine factory (below) or the injected stub. Greedy sampler (`sampler_for(1)` by identity,
     loop/sampling.py:217-234) — a single-draw gate eval and the bake-off are one experiment.
  4. Reduce per-task verdicts through `whetstone.verify.verdict.reduce` (imported by identity);
     count `solved` via `Outcome.SOLVED` by identity; coverage = denominator - unverified (the
     sibling rule, `docs/ROADMAP.md:539`); source A scored in full and reported beside source B,
     both denominators disclosed (`PREREGISTRATION.md:142-147,157`).
  5. `decide(...)`; write the promotion record.
- `src/whetstone/loop/gate.py` — `gate_engine(weights: Weights, checkpoint: Checkpoint, max_tokens:
  int) -> Generator` — the one new machine seam: loads the base + `adapters.safetensors` +
  `adapter_config.json` via `mlx_lm` (function-local import, the exempt package's own rule).
  **Tested only through the seam** (the stub engine is injected in tests); a smoke test asserts
  the factory exists and returns a callable-shaped object without invoking mlx.
- Promotion record: written to `runs/promotions/<id>.json`, schema `whetstone-promotion/1`
  (candidate digest, incumbent digest, held-out document digest, per-side verdict counts over the
  denominator, unverified counts, retries used (aspect 4's field, `0` until that aspect lands),
  `R` (aspect 4's constant, absent until then), the exit, tool versions, `recorded_on` — an
  input, never the clock). `--runs` is refused inside a `reports/` directory (the
  `_refuse_published_root` discipline, night.py:522-544). The home is asserted gitignored.
- `tests/loop/test_gate.py` — fixtures: two fixture checkpoints via `sft.write_checkpoint`
  (stub trainer writing `b"not a tensor, deliberately"`), a fixture held-out document, the

## Testing strategy

- Pure core: the full decision table (promote/reject/UNVERIFIED, `>` term, tie, self-compare,
  regression, single-unverified).
- End-to-end through the stub: fixture checkpoints, fixture held-out document, `Answers` engine —
  the three exits asserted at the CLI boundary, not just the core.
- Adversarial: a doctored checkpoint refuses by name; a hand-edited held-out document refuses;
  the credulous seam (FAIL converted) is impossible by construction, asserted.
- Partition guard: exactly two documented function-local edges; a third fails the build.

## Environment, determinism & locality

- All tests use the stub engine and stub trainer — no model, no GPU, no network, no wall-clock
  dependence (the stub answers instantly).
- `gate_engine` is the operator's real seam; it is never invoked in tests (mlx is an optional
  extra; CI does not install it).
- The promotion record is gitignored local evidence; nothing is published.

## Edge cases

- Candidate == incumbent → `rejected` (asserted).
- Held-out set of zero → refused by name, never vacuous.
- Checkpoint without provenance (not a night-written checkpoint) → refused by name.
- Source A: scored in full, reported beside source B, both denominators disclosed.
- The incumbent's training provenance is out of the gate's question (spec AC) — the gate guards
  the candidate's (night exclusion + check-leakage); state it in the code comment, assert nothing
  about the incumbent's dataset.
