## Testing strategy

- Retry: no-verdict retried to verified; still-unverified after `R` → whole eval `UNVERIFIED`;
  retries used recorded.
- Determinism: same inputs → same sequence.
- Adversarial: FAIL never retried into a win (the credulous retry loses the differential); a
  changed seed or patch is a different experiment and the test refuses it.
- Amendments: test_docs.py green, no proportion, no placeholder, citations exhaustive.

## Environment, determinism & locality

- All tests use the stub engine — no model, no GPU, no network, no wall-clock dependence.
- The retry is pure verification re-execution of identical bytes; the completion hash is the
  identity anchor.
- Nothing leaves the box.

## Edge cases

- A task that times out on every retry: the eval reduces to `UNVERIFIED` — the gate's default is
  *don't promote*; the liveness sentence (unverified rate as a count over its denominator) is in
  the gate's output from the first eval onward (`docs/ROADMAP.md:441-442`).
- Retrying a FAIL: impossible by construction, asserted.
- `RETRY_COUNT` is a constant: a test asserts the CLI has no retry flag (the PRD's declined
  nice-to-have is refused by the parser surface).
