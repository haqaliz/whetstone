   (the probe's and the night's), and used verbatim in the commands and every path that

2. **Probe block.** `--run-id <probe-run-id>`; add `--heldout $REPO/tasks/heldout/source-b.json`;

   `--runs $REPO/runs/night-probe` unchanged. The `check-probe --run` path becomes
   `$REPO/runs/night-probe/<probe-run-id>`; the prose that follows names the same path. Add
   the note (N12) that this probe's ledger will be `whetstone-run/3` and `check-probe` reads
   it through the verifying reader — the historical `probe-001` `/1` ledger is refused, which
   is why the run id is fresh.
3. **New "The held-out set" passage** (before the probe, or as its own section): the § 10.16
   pin in the gate runbook's exact shape —
   *"the held-out source-B split is fixed by `PREREGISTRATION.md` § 10.16 (Type 1,
   2026-09-27), re-derived under the scorable rule — a member is held out only if its oracle
   can be built under the declared budget, the exclusion sealed in the document's rule
   digest"* — plus: the two dev ids `donor-b-353359e9ac6e` and `donor-b-3e3051c4192a` are
   now held-out members; a declared dev id inside the held-out band is exclusion, never a
   refusal (both rules exclude them from training; the gate's eval scores them
   regardless); and the digest read-back halt sentence — after the probe and after the
   night, the ledger's held-out record must name the digest of the committed
   `tasks/heldout/source-b.json`, and a change is a halt, never a rerun.
4. **Night block.** `--run-id <night-run-id>`; add `--heldout $REPO/tasks/heldout/source-b.json`;
   dev ids as above; `--workspace $REPO/runs/<night-run-id>-workspace`; `--runs
   $REPO/runs/nights` unchanged.
5. **Denominator.** Replace the "61 private (66 − 5 dev) + 1 public = 62 tasks" sentence
   with the re-derived arithmetic and its reason: dev overlay first, held-out second
   (`night.py:249-261`) — **51 private (66 − 5 dev − 10 held-out not already dev-excluded) +
   1 public = 52 tasks**, each drawn `K` times.
6. **"After the night"** gains the leakage step after the read-back list, before the byte
   re-verification:
   ```bash
   uv run whetstone check-leakage \
     --run $REPO/runs/nights/<night-run-id> \
     --heldout $REPO/tasks/heldout/source-b.json
   ```
   Prose: exit 0 means source-B examples were compared and none shared a task identity; a
   leak or a refusal names the task / the reason and halts here, before a checkpoint exists;
   a no-example night stays exit 0 ("disjoint by truth"); a tampered held-out document is a
   refusal (exit 2). Note that the gate runbook's step checks the same link at the other end
   — two commanders, belt and braces.
7. **Run-id prose.** "Before the night" → "Declare the inputs" names the two tokens; the
   empty-workspace instruction names `<night-run-id>-workspace` (and the probe's own before
   the probe block); "A killed night" keeps "Restart the **same command, unchanged**" with

   `--run-id`".
8. **Framing.** Header "the first night" → the sheet now commands a *next* night; keep the
