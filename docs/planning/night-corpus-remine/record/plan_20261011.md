### Phase 1 — `TaskSet.remined` and the conditional `_body` (the byte-identity lever)

- **Goal:** AC 1–3, AC 6 and AC 9: the field exists, round-trips sorted and ids-only, emits exactly
  `None → absent` and `() → []`, is covered by the seal, and moves no existing bytes.
- **Prerequisites:** none.
- **Files:** `tests/loop/test_ledger_remine.py` (new), `src/whetstone/loop/ledger.py`.
- **Failing tests first (AC 1, AC 3):**

    through `run_ledger.read` gives a list of `{"task_id", "donor"}` dicts sorted by
    `(task_id, donor)`; feed the pairs reversed to prove the sort is the writer's, not the
    caller's. On the current tree `TaskSet(remined=...)` raises `TypeError` — this is the RED.
  - `remined=None` → `"remined" not in document["task_set"]`; `remined=()` → `document["task_set"]

    `remined: tuple[tuple[str, str], ...] | None = None`, with a docstring that states `None` =
    no re-mine block and `()` = a re-mine that minted nothing, and that it is ids and labels only

  - In `_body`'s `task_set` dict (`ledger.py:409-428`) add the key **conditionally**, in the style

## 4. Testing strategy

- **Unit tests first**, per phase. The `run_night` test reuses the existing `_night` helper rather
  than re-building a night, so the ledger it writes is a real one.
- **Ledger round-trip:** the writer is the only path; assert through `run_ledger.write` +
  `run_ledger.read`, as `tests/loop/test_run_ledger.py:187-206` does.
- **Seal verification:** a mutated nested field is a named `LedgerUnverified` naming `task_set`
  (`seal.py:164-171`); the recompute-everything forger is asserted to **pass** in a test named for
  the limit, so the boundary is executable rather than prose.
- **No-remine byte-identity:** the pinned sha256 of `ledger.document(_ledger())` (fixture, not a
  file — see the spec's Open questions) plus two unflagged nights comparing `ledger.json` bytes.
- **Canary:** `tests/loop/test_run_ledger.py:116-134` stays green unedited, extended by an explicit
  "ids and labels only" test.
- **No nested-shape validator:** Phase 3's tripwire is the guard; it is the one test that would
  force a production change if the code contradicts In scope 4.
- Full-suite run at every phase end; any failure (there is no deliberate-failure window) is a
  stop-and-report.

## 5. Environment, determinism, locality

- **No environment variables** read by the code under test; no model call, no weights, no network,
  no GPU. `uv run pytest` is the whole environment.
- **Determinism:** the field is sorted at the serialization boundary (`_body`), so the same delta
  yields the same bytes whatever order the `remine` aspect minted it in; the `None` path adds no
  key, so an unflagged night is byte-identical to the pre-change tree.
- **Privacy:** `remined` carries `task_id` and a donor **label** only — never a path, never file
  contents. The donor's absolute path lives in the manifests' `repo_url`
  (`../prd.md:143-145`), not here. Nothing leaves the machine.
- **Train/held-out boundary:** the ledger records the delta as ids; it does not read a corpus or a
  held-out document, so it cannot move a held-out member into training.

## 6. Edge cases and error handling

| Case | Outcome |
|---|---|
| `remined=None` (no re-mine block) | no `"remined"` key; `task_set` bytes = pre-change |
| `remined=()` (re-mine ran, minted nothing) | `"remined": []` present — M4's empty recorded delta |
| pairs supplied out of order | sorted by `(task_id, donor)` at serialization; same bytes |
| duplicate `task_id` | not expected (`label-sha12`); stable sort keeps it deterministic, no dedupe |
| `task_id`/`donor` not `str` | a writer bug; the seal canonicalises and the round-trip test's shape assertion catches it — no runtime coercion is added |
| `task_set.remined` mutated after sealing | `LedgerUnverified` naming `task_set` (`seal.py:164-171`) |
| claims and digest recomputed consistently | accepted, `sealed=True` — the documented unkeyed-hash limit, in a named test |
| `/2` ledger (no seal, no `remined`) | read unsealed, byte-unchanged; `remined` absent, never defaulted |
| a pre-change v3 reader handed a remined ledger | accepts: the key is nested, so `verify_claims` re-hashes the whole `task_set` and the top-level claim set is unchanged |
| `morning` / `check_probe` / `honest_report` | ignore the nested key; no `_KNOWN_FIELDS` edit, no refusal |
| schema constant | unchanged (`LEDGER_SCHEMA_V3`); no `/4` bump |
