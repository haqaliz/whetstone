## 2. Implementation phases

### Phase 1 — Expose the node-id reader

- **Goal:** ingestion can mint node ids through the **same** code the verifier compares
  against. Ids minted by a different code path can drift in exactly the ways `_node_id` exists
  to prevent (`strict.py:399-412`), and that drift would surface as every task failing the
  executed-set check with no obvious bug.
- **Prerequisites:** none.
- **Files:** `src/whetstone/verify/strict.py` (rename `_read_report` → `read_report`,
  `_node_id` → `node_id`, keeping `_Case` → `Case` as the returned type; leave every other
  private helper private); new `tests/test_node_ids.py`.
- **RED:** a test that imports `read_report` / `node_id` from `whetstone.verify.strict` and
  asserts the three id shapes pinned at `tests/test_strict.py:338-375` — plain function,
  class-qualified, and **fully parametrised** (`tests/test_a.py::test_param[1-2]`).
- **Watch it fail:** the import error is the RED.
- **Validation:** `uv run pytest tests/test_node_ids.py tests/test_strict.py` exits 0.
- **Note:** this is a rename, not a redesign. Do **not** move the functions to another module —
  they belong next to the comparison that consumes them.
- **Commit:** `Expose the node-id reader for ingestion`

### Phase 2 — Close the path-normalisation hole (C3)

- **Goal:** a `test_blobs` key that is not git's canonical spelling can no longer drop out of
  the patch-**rejection** set (`strict.py:423-434`).
- **DECISION TO MAKE FIRST — reject, don't normalise.** `task.py:89-101` states the loader's
  contract as *"never a silent default"*. Silently rewriting `./tests/x.py` to `tests/x.py` is
  a silent default; rejecting it by name is consistent with all 21 existing refusal paths, and
  the ingester (aspect 2/3) simply emits canonical paths. **If the implementing agent finds a
  reason to prefer normalisation, stop and ask — do not decide it in passing.**
- **Files:** `src/whetstone/verify/task.py` (`_check_blob_path`, `:243-255`);
  `tests/test_task_contract.py`.
- **RED, and it must be watched failing in TWO forms:**
  1. `load_task` accepts `"./tests/test_x.py"` today → assert it now raises `ValueError` naming
     the path. **Watch this fail against today's loader**, which accepts it.
  2. **The hole itself, demonstrated end-to-end before it is closed:** build a fixture task
     whose `test_blobs` key is `"./tests/test_addition.py"`, and a patch that edits
     `tests/test_addition.py`. Assert STRICT **refuses** it. Watch this fail today — it does
     not refuse, because `_held_among` compares the raw manifest string against git's spelling.
     This is the proof the hole was real, not theoretical.
- **Also cover:** `tests//x.py`, a trailing slash, and a `"."` component.
- **Severity note for the commit message:** the unconditional restore
  (`strict.py:160-163`) still writes golden bytes back, so this was a **defence-in-depth hole,
  not a live reward hole**. Say so; do not overstate it.
- **Validation:** `uv run pytest tests/test_task_contract.py tests/test_strict.py` exits 0.
- **Commit:** `Reject non-canonical held paths, closing a refusal-set hole`

### Phase 3 — The `environment` field (ATOMIC — one commit, do not split)

- **Goal:** a manifest determines its own dependency environment, so a verdict cannot be
  decided by the resolver's clock.
- **Why atomic:** `load_task` rejects unknown fields (`task.py:163-170`) and every fixture
  builds its manifest as a literal dict (`tests/fixtures/repos/__init__.py:172-184`). Adding
  the field reds ~19 tests in `tests/test_task_contract.py` **plus every fixture-built verifier
  and adversarial test** until all four sites move together. Splitting this across commits
  leaves the branch red.
- **Files, all in one commit:**
  - `src/whetstone/verify/task.py` — `_FIELDS` (`:51-63`), the `Task` dataclass (`:66-86`), the
    constructor call (`:143-153`), and a new `_environment` validator beside `_provenance`
    (`:258-277`).
  - `tests/fixtures/repos/__init__.py` — `build_task` (`:172-187`) emits the new field.
  - `tests/test_task_contract.py` — `VALID_MANIFEST` (`:42-52`) gains the field; new refusal
    tests.
- **Shape:** `environment: {python: str, pins: tuple[str, ...]}` on the dataclass; frozen, like
  the rest of `Task`. Represent it as a small frozen dataclass, **not** a raw mapping — a
  mapping would make `pins` mutable through a `Mapping[str, Any]` and defeat the frozen
  contract.
- **RED — each watched failing, each rejecting by name:**
  1. a manifest **missing** `environment`;
  2. `pins` containing `click>=8.0` (a range), `click~=8.1`, or a bare `click`;
  3. a non-string entry in `pins`; a non-string `python`;
  4. `pins` **may** be empty (a task with no third-party deps is legitimate) — assert it loads;
  5. round-trip with a **non-UTF-8** blob still byte-identical (extends `:84-96`).
- **Do NOT add** a version field or an `extra` escape hatch. The fail-closed unknown-field rule
  is the contract; weakening it to make this change easier would trade the guarantee for
  convenience.
- **Validation:** full `uv run pytest` back to green (≥119 + new).
- **Commit:** `Add the environment contract to the task manifest`

### Phase 4 — Per-task interpreter in `strict.py`

- **Goal:** a task can run under an interpreter other than the verifier's own 3.12. Verified
  necessary: `requests==2.4.0` cannot import on ≥3.10, `pytest<6.0` needs the removed `imp` on
  3.12 — 11 of 35 source-A candidates are dead on 3.12 today.
- **Files:** `src/whetstone/verify/strict.py` (`verify_strict` signature `:103-110`; the argv at
  `:179`); `tests/test_strict.py`.
- **Design — keep `strict.py` dumb.** Add a keyword-only `interpreter: Path | str | None = None`
  to `verify_strict`; argv uses `str(interpreter) if interpreter else sys.executable`.
  **`strict.py` must NOT resolve `task.environment.python` into a venv path** — provisioning is
  the ingester's job (aspect 3, gate 3). The reward path stays a runner, not a package manager.
- **RED:**
  1. an existing fixture task verified with no `interpreter` yields a **byte-identical**
     `StrictResult` to today's (no behaviour change);
  2. a task run under a nominated interpreter that is a deliberately broken stub yields
     **UNVERIFIED**, not FAIL — an interpreter that cannot run is a "nothing was concluded",
     matching `_exit_status_verdict`'s treatment of rc outside `{0,1}` (`:236-256`);
  3. reads outside the sandbox scope still work (the dig verified an out-of-scope venv
     interpreter is usable under the real profile — `sandbox.py:12-15`, `:114-121`). Assert it
     rather than assume it.
- **Validation:** `uv run pytest tests/test_strict.py tests/test_sandbox.py` exits 0.
- **Commit:** `Let a task nominate its interpreter`

### Phase 5 — The resolver's-clock adversarial test (HARDEST — PRD criterion 7)

- **Goal:** **prove** that pins change the verdict. This is the one new reward-corrupting hole
  the dig found, demonstrated concretely on `pallets__flask-5063` (unbounded `click>=8.0`
  resolved to `click 8.4.2`, removing `CliRunner(mix_stderr=)` and failing 4 `pass_to_pass`
  tests — a **false FAIL**). The user explicitly removed this criterion's escape hatch: it may
  **not** be downgraded to a documented residual.
- **Files:** `tests/fixtures/pkgindex/` (new — a recorded local package index holding two
  versions of one trivial package); `tests/test_environment_pins.py`.
- **Design:** build a tiny local wheel/sdist pair — `whetstone-fixture-dep` at `1.0.0` and
  `2.0.0`, where `2.0.0` removes a keyword argument the fixture test uses. Resolve with
  `uv pip install --offline --find-links tests/fixtures/pkgindex`. **Never the live network** —
  a test whose result depends on what PyPI serves that morning is the very failure being
  guarded against, and would be self-refuting here.
- **RED:** the same task, same patch, same seed:
  - resolved with `pins == ["whetstone-fixture-dep==1.0.0"]` → **PASS**
  - resolved with an unbounded requirement (latest wins → `2.0.0`) → **FAIL**
  Assert the two verdicts **differ**, and assert the FAIL's grounding names the `pass_to_pass`
  breakage, not an incidental error.
- **Anti-vacuity:** assert the index actually contains both versions and that the unpinned
  resolution really selected `2.0.0` — otherwise the test could pass with an empty index.
- **This phase is a likely checkpoint for human review** (see § 7). If building the offline
  index proves harder than budgeted, **stop and surface it** rather than silently weakening the
  criterion.
- **Validation:** `uv run pytest tests/test_environment_pins.py` exits 0, offline.
- **Commit:** `Prove pins decide the verdict, with an offline index`

## 4. Testing strategy

**Unit** — per phase above; each RED watched failing first.
**Integration** — Phase 5 (pins → verdict) and Phase 7 (directory → reduced exit code) are the
two that cross module boundaries.
**Adversarial (mandatory, this aspect touches the reward's inputs):**
1. Phase 2 — a patch editing a held test spelled non-canonically must be **refused**.
2. Phase 5 — unpinned resolution reaches a **different verdict** than pinned.
3. Phase 7 — a directory containing one UNVERIFIED task must **never** exit 0.

**Determinism and no network:** every test in this aspect runs offline. Phase 5's index is
local; `uv pip install --offline` must be asserted, not assumed. The existing determinism test
(`test_the_verdict_is_identical_across_repeated_runs`) must stay green.

**Commands:** `uv run pytest` · `uv run ruff check .` · `uv run mypy src/`.

## 5. Environment, determinism & locality

- **No env vars, no keys, no BYOK anything.** No model is invoked in this aspect; the
  reward-path import guard must stay green and is widened in Phase 8.
- **Determinism:** the sandbox already pins `PYTHONHASHSEED=0` and disables plugin autoload
  (`sandbox.py:232-239`). The `environment` field extends that pinning outward to the
  dependency set — that is the whole point of the aspect.
- **Train/held-out boundary:** untouched. This aspect mints nothing and splits nothing; the
  split is P3's (`whetstone check-leakage`). The format's only obligation to it is carrying
  enough provenance to make the split auditable later.
- **Locality:** nothing leaves the machine. `repo.py` clones a path or URL from the operator's
  manifest and is already proven to work against a local path.

## 6. Edge cases and error handling

| Condition | Outcome | Why |
|---|---|---|
| `environment` missing from manifest | `ValueError` naming the field | Fail-closed; a defaulted environment is a verdict decided by the resolver |
| `pins` contains a range (`>=`, `~=`, bare) | `ValueError` naming the offending pin | A range re-opens the exact hole the field closes |
| `pins` empty | **Loads** | A task with no third-party deps is legitimate |
| Nominated interpreter missing/unrunnable | **UNVERIFIED**, not FAIL | Nothing was concluded — matches `_exit_status_verdict` for rc ∉ {0,1} |
| Non-canonical blob path | `ValueError` naming the path | Consistent with all 21 existing refusals; never a silent rewrite |
| Directory with 1 UNVERIFIED among passes | exit **3** | `verdict.reduce` ranks UNVERIFIED above PASS (`verdict.py:67-73`) |
| **Empty** task directory | **usage error (2)** | An empty set reducing to PASS would be the vacuous-green lie; it is a malformed invocation, not a verdict |
| Task directory containing a non-manifest file | usage error naming the file | No silent skipping — a skipped task is a missing denominator |

## 7. Agent execution notes

**Human review checkpoints — stop and surface, do not decide in passing:**
1. **Phase 2's reject-vs-normalise decision.** The plan recommends *reject*; if the implementing
   agent finds a reason to prefer normalisation, ask.
2. **Phase 5**, if the offline index proves harder than budgeted. The criterion may **not** be
   quietly weakened — the user explicitly removed its escape hatch.
3. **Phase 8's ROADMAP edit**, since `tests/test_docs.py` couples doc prose to
   `tests/adversarial/corpus.py` by import — a careless edit reds the suite for a
   non-obvious reason.

**Likely to need iteration:** Phase 5 (building a valid two-version local index that `uv`
resolves offline) and Phase 3 (the atomic change touches four sites; expect a red suite
mid-edit — that is expected, not a failure).

**Sequencing for parallelism:** Phases 1 and 2 are independent and can run concurrently.
Phase 3 must be a single agent working alone (it reds the suite). Phases 6 and 7 are
independent of 4 and 5.

**Do not:** add a manifest version field or an `extra` escape hatch; move the node-id functions
out of `strict.py`; let `strict.py` resolve environments or install anything; name any module
under a guarded root `models.py`, `judge.py`, or `prompt.py`.
