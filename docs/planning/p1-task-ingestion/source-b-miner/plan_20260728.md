---

## 0. Two decisions taken up front

### D-A: the mint runs only the HELD TEST FILES, not the donor's whole suite

Deriving `fail_to_pass` needs outcomes before and after the fix. Running a donor's entire suite
twice per candidate is the difference between minutes and many hours (belay alone reports 832
tests; contig has 606 commits and 224 mintable candidates).

**So each run invokes pytest on the held test files only.** `fail_to_pass` = ids that flip
`failed`→`passed`; `pass_to_pass` = ids `passed` in both runs **within those same files**.

**What this costs, stated honestly:** a regression elsewhere in the donor's suite would not be
caught by the resulting task. That is a narrower `pass_to_pass` than a whole-suite mint would
give, and it must be recorded in the task's `provenance` (`pass_to_pass_scope: "held-files"`)
so no future reader mistakes the corpus for something broader than it is. It does **not** weaken
the reward — STRICT still asserts the executed set exactly — it bounds what the task is *about*.

### D-B: source-B environments ARE derivable — unlike source A's

Every lockfile donor (contig, belay, whetstone) carries `pyproject.toml` + `uv.lock`. So the
miner provisions with `uv sync` against the donor's own lock and records the resolved set via
`uv pip freeze` as exact `==` pins. **This is the opposite of source A**, where era-pins had to
be determined by hand because the upstream repo declares unbounded ranges. Note the asymmetry in
the module docstring — it is the reason source B is cheap and source A is not.

## 1. Implementation phases

### Phase 1 — Donor git plumbing

- **Goal:** enumerate candidates and extract what each one contains, offline.
- **Files:** `src/whetstone/tasks/donor.py`; `tests/test_donor.py`.
- **API:** `candidates(donor: Path) -> tuple[Candidate, ...]` where `Candidate` carries
  `sha`, `parent`, `subject`, `held_tests` (test files **modified** by the commit),
  `source_paths` (non-test `.py` touched), `other_paths` (non-`.py` touched).
- **Selection rule (PRD D2):** `--no-merges`; ≥1 test `.py` with status `M`; ≥1 non-test `.py`.
  A commit that only *adds* a test file is **excluded** — `strict.py:131-140` refuses a task
  whose held paths do not exist at `base_commit`, and relaxing that is deliberately out of scope.
- **Reuse:** the hardened `_git` wrapper in `tests/fixtures/repos/__init__.py:222-253` neutralises
  machine config and pins identity. **Do not re-derive it** — lift the same discipline
  (`GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` → devnull, `GIT_TERMINAL_PROMPT=0`).
- **RED:** against a synthetic multi-commit donor built by extending `tests/fixtures/repos/`:
  a modify-test commit is selected; an add-test-only commit is **excluded**; a merge is excluded;
  a docs-only commit is excluded. Watch each fail first.
- **Commit:** `Enumerate mintable commits in a local donor`

### Phase 2 — The held set: test files + the cheat-10 conftest floor

- **Goal:** decide exactly which paths become `test_blobs` (PRD D4/M5).
- **Files:** `src/whetstone/tasks/held.py`; `tests/test_held_set.py`.
- **Rule:** the test files the commit modified, **plus every `conftest.py` from the repo root
  down to each held test's directory** that exists at the parent commit.
- **THE OVER-DECLARATION GUARD (spec criterion 6) — this is the dangerous one.** If a held path
  is one the gold patch must change, `strict.py:160-163`'s restore silently overwrites the fix
  and the task becomes **permanently unpassable, reported as an ordinary FAIL** with no
  diagnostic. So: assert `held ∩ gold_patch_paths == ∅`; a candidate that violates it is
  **rejected at mint time**, never minted.
- **RED:** a synthetic candidate whose gold patch touches an auto-held `conftest.py` is rejected,
  and the rejection names the over-declaration. Watch it fail first.
- **Honesty note for the docstring:** this narrows cheat 10, it does not close it. ~22% of
  contig's mintable commits also touch a non-`.py` file (measured: 49/224) that no `conftest`
  rule and no import walk would see. Cheat 10 stays `BOTH_ACCEPT` in the corpus.
- **Commit:** `Hold the test files and every conftest on their path`

### Phase 3 — Node-id derivation

- **Goal:** turn a candidate into `fail_to_pass` / `pass_to_pass`.
- **Files:** `src/whetstone/tasks/derive.py`; `tests/test_derive.py`.
- **Procedure** (per D-A, held files only):
  1. clone donor to a scratch dir, checkout **parent** detached;
  2. overlay the child's versions of the held test files (this *is* the test patch — no separate
     mechanism, see PRD § 5.4);
  3. run pytest over the held files with `--junit-xml`; read via `read_report` (exposed in
     aspect 1) → `outcomes_before`;
  4. apply the gold patch (the commit's **non-test** diff); run again → `outcomes_after`;
  5. `fail_to_pass` = failed→passed; `pass_to_pass` = passed in both;
  6. **flake pass:** repeat step 4's run; any id whose outcome differs is **discarded**, and the
     discard is recorded in provenance. A flaky id makes a task whose verdict is noise.
  7. reject the candidate if `fail_to_pass` is empty (`load_task` would reject it anyway).
- **Ids are minted via `node_id`/`read_report` from `strict.py`** (aspect 1, Phase 1) — never
  hand-constructed, never `--collect-only`. Drift between minting and comparison presents as
  every task failing the executed-set check with nothing to explain it.
- **RED:** a synthetic candidate yields exactly the expected ids; a **parametrised** test yields
  a fully-parametrised id; a deliberately flaky test is discarded, not recorded.
- **Commit:** `Derive node ids from the red and green runs`

### Phase 4 — Environment capture

- **Goal:** every minted task carries exact `==` pins (aspect 1's contract).
- **Files:** `src/whetstone/tasks/environment.py`; `tests/test_environment_capture.py`.
- **Rule (D-B):** `uv sync` the clone against the donor's own `uv.lock`, then `uv pip freeze` the
  resulting venv and record the output as `pins`. `python` = the interpreter actually used.
- **A donor with no lockfile** (rereflect's services) → capture is not possible from a lock;
  either resolve from its requirements and record what was resolved, or **reject the donor with
  a named reason**. Do not emit an empty `pins` and pretend the environment is captured — an
  empty `pins` means "no third-party dependencies", which would be a lie about a Django service.
- **RED:** captured pins are all exact `==`; a donor without a lockfile is rejected by name.
- **Commit:** `Capture the donor's resolved environment as exact pins`

### Phase 5 — Liveness, the ledger, and the recipe

- **Goal:** nothing enters the corpus unproven (PRD M8, § 3.1).
- **Files:** `src/whetstone/tasks/liveness.py`; `src/whetstone/tasks/ledger.py`;
  `tests/test_liveness.py`; `tests/test_ledger.py`.
- **Liveness, per minted task:** `verify_strict(task, empty_patch)` → **FAIL**;
  `verify_strict(task, gold_patch)` → **PASS** with `executed == declared` and **zero skips**.
  Either result missing → the task is discarded and the reason recorded.
- **THE VACUOUS-TASK CONTROL (spec criterion 4) — watched failing first.** A task that passes
  with **no patch** must fail the build. This is the control that stops ingestion paying reward
  for nothing, and it is the single most important test in this aspect.
- **Ledger** → `tasks/local-ledger.json`, committed: `task_id`, **manifest hash** (sha256 of the
  manifest bytes), both verdicts, `executed == declared`, skip count, interpreter, tool versions,
  date. **Hashes and verdicts only — never file contents.** A structural test asserts no value in
  the ledger contains a blob, a diff, or a source line.
- **Recipe** → `tasks/recipes/<donor>.json`, committed: donor path, selection filters, tool
  versions, mining date, and the `pass_to_pass_scope` decision from D-A.
- **Commit:** `Prove every minted task live, and commit the evidence`

### Phase 6 — The `whetstone mine` subcommand

- **Goal:** the operator-facing surface.
- **Files:** `src/whetstone/cli.py`; `tests/test_mine_cli.py`.
- **Shape:** `whetstone mine --donor <path> --out tasks/local/<name>/ --limit N [--seed S]`.
  Deterministic selection under a seed so a re-run mints the same candidates.
- **Exit codes:** reuse the existing four. No fifth (`tests/test_verify_cli.py:220-224`).
- **RED:** mining a synthetic donor end-to-end writes manifests `load_task` accepts, a ledger,
  and a recipe; `--limit 0` is a usage error, not a silent empty corpus.
- **Commit:** `Add the mine subcommand`

### Phase 7 — The real mint

- **Goal:** an actual corpus. **This phase runs locally, not in CI.**
- **Target (PRD D5):** 60–80 tasks stratified across contig, belay, whetstone, rereflect.
- **Order:** contig (largest, 224 mintable) → belay (49) → whetstone (2) → rereflect **last**
  (per-service, no root lockfile, unbounded by the estimate — PRD N2).
- **CI boundary (PRD § 8.2):** real-donor mining is **excluded from CI**. Reprovisioning donors
  per run makes a red build ambiguous between "the task regressed" and "the environment flaked",
  and an ambiguous red is a verdict decided by the harness. CI covers the synthetic donor; the
  real mint's evidence is the committed ledger.
- **Report the actual number, whatever it is.** If the stratified target is not reached — a donor
  fails to provision, a class of candidate is rejected — the shortfall and its cause are
  recorded, never rounded up to the target.
- **Commit:** `Mint the source-B corpus` (+ ledger and recipes)

## 2. Testing strategy

**Everything except Phase 7 runs on a SYNTHETIC donor** built by extending
`tests/fixtures/repos/` to a multi-commit history — deterministic (its git identity and dates
are already pinned, so SHAs are stable across machines), fast, and offline.

**Adversarial / honesty tests, all watched failing first:**
1. **The vacuous-task control** (Phase 5) — a task passing with no patch fails the build.
2. **The over-declaration guard** (Phase 2) — a candidate whose gold patch touches a held path is
   rejected at mint time.
3. **The cheat-10 differential** (Phase 2) — a task omitting a `conftest.py` on the path to a
   held test is rejected by *that rule*, and the assertion names it. The same task hand-authored
   without the rule is accepted by both verifiers, proving the differential is real.
4. **No network** (spec criterion 1) — an AST guard asserts the source-B path imports no network
   client, with an anti-vacuity control proving the walk sees real imports.
5. **The ledger carries no contents** — structural assertion.

## 3. Edge cases

| Condition | Outcome |
|---|---|
| Candidate's `fail_to_pass` empty after derivation | Discard, record reason |
| An id flaky across the repeat run | Discard that id; if it was the only `fail_to_pass`, discard the task |
| Gold patch touches an auto-held `conftest.py` | **Reject the candidate** — never mint a permanently-unpassable task |
| Donor has no lockfile | Reject the donor by name; never emit empty `pins` as if captured |
| Donor's suite cannot provision | Record and skip; the shortfall is reported, not hidden |
| Liveness FAIL-then-PASS not observed | Discard the task, record which half failed |
| `--limit 0` | Usage error |

## 4. Agent execution notes

**Checkpoints — stop and surface:**
1. **Phase 7**, before mining at scale, if provisioning any donor fails.
2. **Phase 4**, if `uv pip freeze` output turns out not to be usable as `==` pins.
3. Any temptation to relax the vacuous-task control or the over-declaration guard.

**Do not:** run a donor's whole suite (D-A); hand-construct node ids; mine commits that only add
a test file; commit anything from `tasks/local/`; let the miner touch the network.
