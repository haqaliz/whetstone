## Testing strategy

- Guards read committed documents; they are deterministic, offline, and need no model.
- Each new guard is shown failing against the pre-change tree (RED), or — where it pins behaviour
  that already exists — shown live by removing the property and watching it fail (the repo's
  watched-failing-first discipline).
- Adversarial: not applicable (off the reward path); say so in the commit body.
- Confidence check: `uv run pytest -q`, `uv run ruff check .`, `uv run mypy src/`.

## Environment, determinism & locality

- No env vars, no weights, no network. Nothing leaves the machine.
- Train/held-out boundary: untouched — no task data is read or written.

## Edge cases & error handling

- `PREREGISTRATION.md` forbids `%`/`percent`/placeholder tokens and must keep 11 `## ` headings —
  the Phase 1 guard's negative half must still pass.
- `ROADMAP_CITATIONS` (`tests/test_docs.py:141-152`) must still resolve: corrections are appended,
  not inserted, so no cited line range moves.
- No `UNVERIFIED` path: no evaluation.
