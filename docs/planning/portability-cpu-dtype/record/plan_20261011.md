## Implementation phases

### Phase 1 — the field and the record

- **Goal:** `Backend` carries an optional precision, `recorded()` emits it, and the gate refuses a
  pair differing only in precision.
- **Prerequisites:** none.
- **RED:** in `tests/loop/test_backend.py`:
  - extend `test_the_record_is_json_plain_and_distinguishes_the_backends` (`:150-176`) so its
    `set(recorded) == {...}` includes `"precision"` — watched failing first;
  - add `test_the_precision_is_recorded_and_defaults_to_none`: a `Backend(...)` with no `precision`
    records `None`, and one with `precision="bfloat16"` records `"bfloat16"`;
  - add `test_a_precision_mismatch_is_refused_and_a_match_is_not`, calling
    `gate.refuse_cross_backend` with two `Backend(...).recorded()` dicts that differ **only** in
    `precision` (expect `MismatchedBackend`) and two that are identical (expect no raise).
  Run `uv run pytest tests/loop/test_backend.py -q` → **fails** (`precision` is not a key).
- **GREEN:** add `precision: str | None = None` as the **last** field of `Backend`
  (`backend.py:93-131`) and `"precision": self.precision` to `recorded()`. Re-run → passes.
- **REFACTOR:** keep `recorded()`'s field-by-field docstring note intact.
- **Files:** `tests/loop/test_backend.py`, `src/whetstone/loop/backend.py`.
- **Validation:** `uv run pytest tests/loop/test_backend.py -q` green.
- **Commit:** `portability-cpu-dtype: the backend record carries the precision (TDD)`

## Testing strategy

- Unit: the field/record tests (AC3), the describer tests (AC2), the gate refusal (AC5).
- Integration: checkpoint + ledger `backend` blocks (AC4) — real writers, fake adapter files
  (the `test_backend.py:221-264` pattern), no model, no network.
- Deterministic: describers are exercised only where the runtime is installed; otherwise the test
  skips loudly (`pytest.skip` naming the artefact), exactly as the existing MLX/CUDA tests do.
- Adversarial: none — off the reward path. State it in the commit body.

## Environment, determinism & locality

- No env vars, no weights, no network. Nothing leaves the machine.
- Train/held-out boundary: untouched.

## Edge cases & error handling

- A checkpoint carrying a `backend` **without** `precision` (the v1 arm checkpoint) is refused
  against a new precision-bearing candidate by the whole-dict `==` — correct, and pinned.
- A `backend` of `None` (untrained) is exempt; AC5 pins it.
- `verify_checkpoint` must not reject the extra nested key — pinned by the AC4 guard; if it does,
  the fix is in `verify_checkpoint`'s tolerance, never a schema bump.
- No `UNVERIFIED` path: nothing is evaluated.
