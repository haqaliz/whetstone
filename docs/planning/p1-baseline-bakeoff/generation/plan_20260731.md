## 0. A design decision this plan makes, and why

`src/whetstone/` holds `verify/`, `tasks/`, `__init__.py` and **`cli.py`**. `GUARDED_ROOTS`
(`tests/test_no_inference_on_reward_path.py:77`) names only the two packages — so **`cli.py` is
unguarded today**, despite being the reward's entry point (`cli.py:248-250` calls `verify_strict`).
A partition guard that enumerates only packages would reproduce that blind spot.

**Decision:** the partition guard covers **every** package *and* every top-level module under
`src/whetstone/`, and `cli.py` is added to the guard's scope — not to make anything pass, but
because it is reward-path code that nothing was watching. `CONTRIBUTING.md:20` forbids widening the
guarded path *to make a failing check pass*; widening it to cover code it should always have
covered is the opposite act, and the plan records the distinction so a reviewer can judge it.

**Consequence, and it is binding on later aspects:** with `cli.py` guarded, the bake-off may
**not** be exposed as a `whetstone bakeoff` subcommand — `cli.py` would then import the package
that imports `mlx_lm`, and the guard walks function-local imports too (`ast.walk`, `:188-213`), so a
lazy import would not evade it. The runner is therefore invoked as `python -m whetstone.bakeoff`.
**PRD nice-to-have N2 is dropped**, deliberately, and this is the reason.

## 2. Implementation phases

Six phases, each RED → GREEN → REFACTOR, each leaving the suite green and committable.

### Phase 1 — The partition guard (do this first, before the package exists)

- **Goal:** a test that fails the build when a package or top-level module under `src/whetstone/` is
  neither guarded nor explicitly exempted with a written reason. Written **first** so it is watched
  failing against a tree that has the hole, which is the only way to know it works
  (`CONTRIBUTING.md:53-60`).
- **Prerequisites:** none.
- **Files:** create `tests/test_reward_path_scope_is_partitioned.py`; modify
  `tests/test_no_inference_on_reward_path.py` to add `SRC/"whetstone"/"cli.py"` to `GUARDED_ROOTS`
  (see § 0) — note `_modules` currently calls `root.rglob("*.py")`, which returns nothing for a file
  path, so the helper needs to accept a file root, and its per-root non-emptiness assertion
  (`:152-160`) must keep working for both shapes.
- **The guard asserts:** (a) the enumerated set of packages + top-level modules is **non-empty**;
  (b) every entry is guarded or on `EXEMPT`, a mapping from name to a written reason; (c) `EXEMPT`
  contains no name that no longer exists (a stale exemption is a hole with a comment on it).
- **Watched failing:** against a synthetic tree containing an unlisted package, and against a
  synthetic `EXEMPT` naming a package that does not exist.
- **Validation:** `uv run pytest tests/test_reward_path_scope_is_partitioned.py tests/test_no_inference_on_reward_path.py`
- **Commit:** `Watch the packages the reward-path guard never looked at`

### Phase 2 — The model boundary, with no model behind it

- **Goal:** the seam every later test substitutes. A `Generator` protocol with one method, plus a
  deterministic stub for tests.
- **Prerequisites:** Phase 1.
- **Files:** `src/whetstone/bakeoff/__init__.py`, `src/whetstone/bakeoff/generator.py`;
  `tests/bakeoff/test_generator_contract.py`.
- **Notes:** module names must avoid the exact components `model`, `models`, `llm`, `judge`,
  `inference`, `completion`, `prompt`, `prompts` (`:134-136`) — cheap insurance even though nothing
  guarded imports this package. `generator.py` and `patch.py` are safe; `prompt.py` is **not**.
- **Validation:** `uv run pytest tests/bakeoff/` — passes with mlx absent. Also confirm Phase 1's
  guard still passes now that `bakeoff/` exists and is listed in `EXEMPT` with its reason.
- **Commit:** `Put a seam where the model will go`

### Phase 3 — The prompt contract

- **Goal:** `Task` → prompt string, deterministic and content-hashed.
- **Prerequisites:** Phase 2.
- **Files:** `src/whetstone/bakeoff/rendering.py` (name chosen to avoid the banned components);
  `tests/bakeoff/test_prompt_contract.py`.
- **Content:** `problem_statement` plus the declared `fail_to_pass` node ids — the smallest
  defensible contract, chosen to be *disclosed rather than tuned* (PRD M7b).
- **Must not include** `test_blobs` content. Showing the policy the operator-held tests would hand
  it the answer key and make the special-casing residual (cheat 6) trivial to hit; the sandbox
  already allows reads wholesale (`sandbox.py:12-18`), so the prompt should not make it easier.
  **A test asserts no held-test content appears in the rendered prompt.**
- **Validation:** `uv run pytest tests/bakeoff/test_prompt_contract.py`
- **Commit:** `Fix what a base is shown, and hash it`

### Phase 4 — The diff extractor

- **Goal:** model text → a unified diff, or an explicit no-diff outcome. **The highest-value phase
  in this aspect** — spec AC4 and AC5 both live here.
- **Prerequisites:** Phase 2.
- **Files:** `src/whetstone/bakeoff/patch.py`; `tests/bakeoff/test_extraction.py`.
- **Return type:** a two-case result (e.g. `Extracted(diff: str)` vs `NoDiff(reason: str)`).
  **Never `""`** — `verify_strict(task, "")` is charged `FAIL` at `patch-apply`
  (`liveness.py:14-20`), indistinguishable from a wrong fix, which is precisely what would make P1's
  pivot signal unreadable.
- **Must not sanitise.** A diff touching a path in `test_blobs` is passed through **unmodified**;
  STRICT's `patch-scope` refusal (`strict.py:524-533`) is the defence, and an extractor that
  repaired the patch would convert a caught cheat into an uncaught one.
- **Cases to cover:** fenced ```diff block; fenced block with no diff; bare diff; prose only; empty
  string; multiple fenced blocks; a diff followed by trailing prose; CRLF line endings; a diff whose
  paths are absolute rather than `a/`…`b/` (git applies relative to the checkout root, `repo.py`).
- **Validation:** `uv run pytest tests/bakeoff/test_extraction.py`
- **Commit:** `Tell a missing diff apart from a wrong one`

### Phase 5 — The MLX adapter

- **Goal:** the one place `mlx_lm` is imported.
- **Prerequisites:** Phases 2–4.
- **Files:** `src/whetstone/bakeoff/mlx_runtime.py`; `tests/bakeoff/test_mlx_runtime.py`;
  `pyproject.toml` (mypy overrides).
- **API, pinned to `mlx-lm==0.31.3`:** `mlx_lm.utils.load(path_or_hf_repo, ..., revision=...)`
  (`utils.py:453`) and `mlx_lm.generate.generate(model, tokenizer, prompt, ...)`
  (`generate.py:756`). Sampling is injected as a **callable**, not a `temperature=` argument; greedy
  is the default (`generate.py:386`) and needs no seed.
- **Load from a local directory only.** `load()` decides by a plain `Path.exists()` check
  (`utils.py:218-256`): a directory loads offline, a bare repo id is a network call. A test asserts
  the adapter is constructed with a filesystem path and never a repo id.
- **Import discipline:** `import mlx_lm` sits inside the adapter module only. Tests for this module
  skip **loudly** when `importlib.util.find_spec("mlx_lm") is None` — the style `ci.yml:33-74` models
  with `-rs`, because `tests/conftest.py:66-69` treats a silent skip as the same class of lie as
  rendering `UNVERIFIED` as `PASS`.
- **Validation:** `uv run pytest tests/bakeoff/ -rs` with and without `--extra mlx`;
  `uv run mypy src/` must pass **without** mlx installed.
- **Commit:** `Load a base from disk, greedily, or not at all`

### Phase 6 — Weights cannot be committed

- **Goal:** the ignore rule, proven.
- **Prerequisites:** none (can run in parallel with 2–5).
- **Files:** `.gitignore`; `tests/test_bakeoff_layout.py`.
- **Method:** copy the established shape — `_check_ignore` via `git check-ignore -v`
  (`tests/test_tasks_layout.py:36-43`) — and honour the trailing-slash trap (`:15-19`): a
  directory-only pattern reports "not ignored" for the no-slash spelling while the directory is
  absent, which is a false alarm, not a missing rule. Assert **both** spellings deliberately.
- **Validation:** `uv run pytest tests/test_bakeoff_layout.py`
- **Commit:** `Refuse to commit a model`

## 4. Testing strategy

Acceptance criteria are lifted from `generation/spec.md` AC1–AC9; this section maps them to phases.

| AC | Phase | Test |
|---|---|---|
| AC1 guard passes, not widened for `bakeoff` | 1 | `bakeoff` appears in `EXEMPT` with a reason, **not** in `GUARDED_ROOTS` |
| AC2 partition guard, watched failing *(adversarial)* | 1 | Synthetic tree with an unlisted package fails; synthetic stale exemption fails; enumerated set asserted non-empty |
| AC3 green with mlx absent | 2–5 | Full suite under plain `uv sync`; mlx tests skip loudly with `-rs` |
| AC4 no-diff ≠ empty patch *(adversarial)* | 4 | The two outcomes are distinct at the type level; `NoDiff` is never rendered as `""` |
| AC5 extractor is not credulous *(adversarial)* | 4 | A diff touching a `test_blobs` path survives extraction unmodified |
| AC6 prompt deterministic and hashed | 3 | Byte-identical across calls and processes; stable hash; **no held-test content** |
| AC7 deterministic stub; greedy MLX | 2, 5 | Stub repeatability; adapter requests greedy and takes a path, never a repo id |
| AC8 weights not committable | 6 | `git check-ignore -v`, both slash spellings |
| AC9 gates green | all | `ruff check .`, `mypy src/`, `pytest`, `whetstone --help` |

**Determinism and network.** Every test in this aspect is pure: no model, no network, no wall-clock
dependence, no `mlx` requirement except Phase 5's loudly-skipped tests. Nothing here calls the
reward, so no adversarial *verifier* test belongs in this aspect — the reward-facing adversarial
work is aspect 2's AC2/AC5. The adversarial tests here (AC2, AC4, AC5) target the *generation* side:
each is a case that would pass under a naive implementation and must fail under this one.

**Train/held-out boundary.** Untouched. This aspect reads no corpus, defines no split, and produces
no number. § 7.1 of `PREREGISTRATION.md` stays open and unspent.

## 5. Environment, determinism & locality

- **No new environment variables.** No API keys: there is no cloud teacher in this slice and
  `docs/ROADMAP.md` places BYOK distillation post-horizon.
- **Pinning:** `mlx-lm==0.31.3` / `mlx==0.32.0` are already in `uv.lock`. The adapter takes a model
  **path** plus a `revision`; weight provenance is recorded by aspect 4, not here.
- **Determinism:** greedy decoding is the default sampler and needs no seed — VERIFIED byte-identical
  across runs. Note `mx.random.seed` is **global process state** with no `seed=` kwarg, which
  constrains any future in-process parallelism; recorded now so aspect 4 does not rediscover it.
- **Locality:** nothing leaves the machine. The only inbound network in the whole slice is the
  human-run weight fetch (aspect 4) and source A's per-run `git clone` (aspect 2/4), both disclosed.
  This aspect adds neither.

## 6. Edge cases & error handling

| Case | Outcome |
|---|---|
| Model emits prose, an empty string, or a fenced block with no diff | `NoDiff(reason)` — explicit, never `""`. Aspect 2 records it distinctly; aspect 3 publishes the count |
| Model emits a diff touching a held test | Passed through unmodified; STRICT refuses it at `patch-scope`. **Not** repaired here |
| Model emits several fenced blocks | Documented, deterministic choice (first well-formed diff), asserted by test — not left to chance |
| Model output truncated mid-diff | `git apply` refuses ⇒ STRICT `FAIL` at `patch-apply`. Aspect 3 reports `patch-apply` counts separately so this is visible rather than absorbed |
| `mlx_lm` absent | Adapter import fails loudly at construction with a message naming `uv sync --extra mlx`; the rest of the package is unaffected |
| Model directory missing or not a model | Raise with the path named. **Never** fall back to a repo id — that would silently turn an offline run into a network one |
| Non-darwin platform | Not this aspect's concern (nothing here sandboxes); aspect 2 owns `UnsupportedPlatform` → `UNVERIFIED` |

**No silent pass anywhere.** Nothing in this aspect may return a default that reads as success:
`NoDiff` is a first-class outcome, not an empty string standing in for one.

## 7. Agent execution notes

**Checkpoint for human review after Phase 1** — it changes `GUARDED_ROOTS`, which is the project's
central guardrail. § 0's reasoning should be re-read and agreed before the rest is built on it.

**Second checkpoint after Phase 4** — the extractor's behaviour determines whether the eventual
number is interpretable at all (spec AC4/AC5, PRD R1). Worth reading the tests, not just the green
tick.

**Likely to need iteration:** Phase 4 (real model output is messier than fixtures) and Phase 1's
`_modules` change (it must accept both a directory root and a file root while keeping its per-root
non-emptiness assertion meaningful).

**Ask before proceeding if:** the partition guard's exemption mechanism seems to want `bakeoff`
added to `GUARDED_ROOTS` "just to be safe" — that would fail the build the moment the adapter lands
and is the wrong instinct; or if any test starts needing the network or a real model.

**Do not, in this aspect:** call `verify_strict`, read the corpus, produce any figure, add a CLI
subcommand (§ 0), or touch `CLAUDE.md`, `docs/ROADMAP.md`, `PREREGISTRATION.md` or `CHANGELOG.md` —
those belong to aspect 5 and land with the report.

**Spec ambiguity flagged:** `generation/spec.md` leaves open whether the exemption list lives in the
test or in a committed data file. This plan puts it in the test as an `EXEMPT` mapping of name →
reason, because a reason that lives beside the assertion is harder to let go stale — and Phase 1
asserts the mapping names nothing that has ceased to exist.
