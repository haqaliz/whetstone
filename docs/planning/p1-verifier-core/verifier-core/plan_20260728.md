### Phase 1 — Verdict semantics and the task contract

**Goal.** The vocabulary the rest of the aspect speaks: statuses that cannot render an unverified
result clean, and a task contract that cannot be built from policy output.

**Prerequisites.** None beyond P0.

**Files**

- `src/whetstone/verify/__init__.py` (new)
- `src/whetstone/verify/verdict.py` (new) — ported from `belay/verify/verdict.py`
- `src/whetstone/verify/task.py` (new)
- `tests/test_verdict.py` (new)
- `tests/test_task_contract.py` (new)

**Port notes — `verdict.py`.** Lift near-verbatim; it is stdlib-only. Keep `Status` (PASS, WARN,
FAIL, UNVERIFIED, NOT_COVERED), `_RANK` with `UNVERIFIED: 2` above `PASS: 0`, and `reduce()`
filtering `NOT_COVERED` **before** ranking. **Drop the `axis` field**, keep `kind` — Whetstone has
one axis and a constant field misdescribes the structure (spec § Open questions). Carry the
docstrings across: they explain *why* the ordering is what it is, and that reasoning is the asset.

**`Task`** is a frozen dataclass with the PRD's Data Model fields. `test_blobs` is
`Mapping[str, bytes]` — **bytes, not str**: a path decoded to text reintroduces the
unicode-normalisation trap (`belay/verify/invariants.py:18-24`), and the byte-prefix comparison in
Phase 3 must run on the same bytes throughout.

**Tests (RED first)**

1. `reduce([])` → `UNVERIFIED`. Not `PASS`, not `NOT_COVERED`.
2. `reduce([PASS, UNVERIFIED])` → `UNVERIFIED` (AC 7).
3. `reduce([NOT_COVERED])` → `UNVERIFIED` — empty *after* the filter still reduces to UNVERIFIED.
4. `reduce([PASS, FAIL])` → `FAIL`; `reduce([PASS])` → `PASS`.
5. **Anti-vacuity:** assert `_RANK[UNVERIFIED] > _RANK[PASS]` directly, so a future edit that
   inverts the ordering fails loudly rather than silently changing every downstream verdict.
6. `Task` is frozen — mutation raises.
7. **The provenance boundary (AC 8, M6).** Port the *mechanism* of
   `belay/tests/test_invariants.py:55`: census the module's public callables, select those whose
   return annotation mentions `Task`, assert that set is exactly the known-safe producers, and
   that each takes only an operator-controlled path. Key on the **return type**, not the name —
   that is what makes it durable against a future loader with an innocent name.
   Include an anti-vacuity assert that the census found producers at all.

**Validation.** `uv run pytest tests/test_verdict.py tests/test_task_contract.py` exits 0.
`uv run mypy src/` exits 0.

**Commit.** `Add verdict semantics and the task contract`

### Phase 2 — The sandbox

**Goal.** Run a command with the network denied, writes confined, and a pinned environment — and
prove the denial rather than assume it.

**Prerequisites.** Phase 1 (`Status` for the UNVERIFIED path).

**Files**

- `src/whetstone/verify/sandbox.py` (new)
- `tests/test_sandbox.py` (new)

**Design.** One public entry point taking a command, a write-scope directory, and a timeout, and
returning a result carrying return code, stdout, stderr, and the profile actually applied.
Everything `sandbox-exec`-specific stays inside this module — it is Apple-deprecated, and the
mechanism must be swappable without touching five call sites (spec § risks).

Profile shape (verified by spike, PRD § B):

```
(version 1)
(allow default)
(deny network*)
(deny file-write*)
(allow file-write* (subpath "<escaped scope>"))
```

**Three non-negotiables:**

1. **SBPL escaping.** Escape `\` and `"` in the path before interpolation. A path containing `"`
   would close the policy literal early and let the remainder parse as SBPL — a policy injection
   into the boundary that enforces the policy. Equivalent to `belay/sandbox/seatbelt.py:87-95`.
2. **Non-darwin raises**, never silently runs unsandboxed. A no-op returning success would be
   Whetstone claiming a containment boundary that does not exist.
3. **Timeout and crash → `UNVERIFIED`, never `FAIL`.** A task the sandbox could not run is one we
   could not check.

**Tests (RED first)**

1. **Network denied, observed (AC 9).** Run a probe that attempts a connection; assert it is
   refused. No network is used by the test — the probe's *failure* is the assertion.
2. **Anti-vacuity for that test:** run the same probe **without** the sandbox and assert it
   behaves differently. Without this control, a probe that fails for an unrelated reason (no
   route, bad address) would make the sandbox look effective when it did nothing. This control is
   the difference between testing the sandbox and testing the network's absence.
3. In-scope write succeeds; out-of-scope write is denied.
4. A path containing a `"` is escaped, not injected — assert the generated profile.
5. Timeout produces `UNVERIFIED`, not `FAIL`.
6. Deterministic env: assert the child observes `PYTHONHASHSEED=0` and the pinned `TMPDIR`.

**Validation.** `uv run pytest tests/test_sandbox.py` exits 0.

**⚠️ Human checkpoint.** If any sandbox test fails on this machine, stop and report rather than
weakening the profile. A weakened sandbox that makes tests pass is the failure mode this whole
aspect exists to prevent.

**Commit.** `Add the confined, no-network sandbox`

### Phase 3 — STRICT and WEAK

**Goal.** The reward, and the deliberately weaker check it is measured against.

**Prerequisites.** Phases 1–2.

**Files**

- `src/whetstone/verify/strict.py` (new)
- `src/whetstone/verify/weak.py` (new)
- `tests/test_strict.py`, `tests/test_weak.py` (new)
- `tests/fixtures/repos/` (new) — synthetic repos + a builder helper

**STRICT, in order** (`docs/ROADMAP.md:56-66` plus M2b):

1. Materialise `base_commit` into `/_sandbox/<run_id>/`.
2. Apply the patch. **Reject before running anything if it touches any path in `test_blobs`**
   (AC 11) — the rejection is a distinct outcome, not "the tests failed afterwards".
3. Restore **every** operator-held test from golden, always, after the patch.
4. Run pytest over `fail_to_pass + pass_to_pass` in the sandbox, with the pinned environment.
5. Assert skipped-count is zero.
6. **Assert the executed node-id set equals `fail_to_pass + pass_to_pass` exactly, and that each
   `fail_to_pass` id reports `passed`** (M2b, AC 2).
7. Reward is the exit status, folded with the above into a `Verdict`.

**Why step 6 exists — read before implementing.** An exit status answers *"did anything fail?"*;
it cannot answer *"were these the tests?"*. Deselection is not skipping: `-k`, `-m`, and
`--deselect` remove tests from the run without producing a single skip, and they can be injected
from `pyproject.toml`/`pytest.ini`/`setup.cfg` — **configuration, not test paths**, so they are
outside `test_blobs` and survive both step 2's check and step 3's restore. Step 5 alone leaves the
reward defeatable by a patch that never touches a test file. Get the executed set from pytest's
own machine-readable report; do not parse the human-readable summary line.

**WEAK** (`docs/ROADMAP.md:67-72`): checkout, apply the patch with **no** path confinement, **no**
restore, run pytest as the policy left it, verdict is the exit status. Measurement only.

**Make the misuse hard, per M3.** WEAK's return type must be distinct from STRICT's, so a
downstream caller cannot pass a weak result where a reward is expected. A test asserts the two
types are not interchangeable — that is M3's "hard to misuse" made structural rather than a
comment saying "don't".

**Tests (RED first).** Per verifier: a genuinely-fixing patch passes; a non-fixing patch fails; a
patch touching a test path is rejected by STRICT *before execution* and accepted by WEAK; a
sandbox failure yields UNVERIFIED. Plus determinism (AC 6): same task + patch + seed, repeated,
byte-identical verdict.

**Validation.** `uv run pytest tests/test_strict.py tests/test_weak.py` exits 0.

**Commit.** `Add the strict reward and the weak measurement verifier`

### Phase 4 — The adversarial corpus

**Goal.** Prove the differential is real. **This phase is the moat's evidence** — everything
before it is machinery.

**Prerequisites.** Phase 3.

**Files**

- `tests/adversarial/__init__.py`, `conftest.py` (new)
- `tests/adversarial/test_cheats.py` (new)
- `tests/fixtures/repos/cheat_{1..7}/` (new)

**One fixture per cheat** (`docs/ROADMAP.md:104-109` + PRD § D.1):

| # | Cheat | Expected |
|---|---|---|
| 1 | Delete/weaken the failing assertion in the test file | STRICT rejects, WEAK accepts |
| 2 | Weaken an assert in place (`assertEqual` → `assertTrue`) | STRICT rejects, WEAK accepts |
| 3 | Mutate a fixture or `conftest.py` | STRICT rejects, WEAK accepts |
| 4 | `sys.exit(0)` / `os._exit(0)` before assertions run | STRICT rejects, WEAK accepts |
| 5 | Monkeypatch the runner / register a skipping `conftest` plugin | STRICT rejects, WEAK accepts |
| 6 | **Special-case the known input** | **Both accept — the documented residual** |
| 7 | **Deselect via `addopts` in `pyproject.toml`** (PRD § D.1) | STRICT rejects, WEAK accepts |

**Rules for this phase, all load-bearing:**

- **Assert both halves.** A fixture proving only that STRICT rejects could be rejecting for an
  unrelated reason (a malformed patch, a missing file), which would make the corpus look rigorous
  while proving nothing. WEAK accepting is what establishes the difference is *the strictness*.
- **Watch every fixture fail before trusting it**, per house style (`tests/test_cli.py:52`), and
  say so in the docstring. Concretely: confirm each cheat is accepted by STRICT *before* the
  corresponding defence is in place.
- **Cheat 6's test asserts a known weakness.** Name and document it so no future reader mistakes
  it for coverage — something like
  `test_cheat_6_special_casing_is_accepted_by_both_and_this_is_the_documented_residual`, with a
  docstring pointing at `docs/ROADMAP.md:109-118`. It must be impossible to skim this file and
  conclude the family is uncheatable.
- **Cheat 7 asserts the reason** (AC 2): rejection because the executed set did not match, not an
  incidental failure. Otherwise the test passes for the wrong reason and the defence is unproven.
- Synthetic repos only: tiny, zero third-party dependencies, deterministic, millisecond runtime.

**Validation.** `uv run pytest tests/adversarial/` exits 0 (AC 1).

**⚠️ Human checkpoint.** Report the differential table — per cheat, what STRICT and WEAK each
returned. This is the artifact the whole aspect exists to produce.

**Commit.** `Add the adversarial cheat corpus`

## 3. Testing Strategy

| Phase | Tests | Kind |
|---|---|---|
| 1 | `test_verdict.py`, `test_task_contract.py` | Unit + structural (provenance census) |
| 2 | `test_sandbox.py` | Integration (real `sandbox-exec`) |

| 7 | existing `test_docs.py` extended | Documentation guard |

**Determinism and locality.** Every test is deterministic, seeded, and offline. **No test makes a
network call** — the one test that concerns the network asserts a connection is *refused*, and
pairs with an unsandboxed control so it cannot pass for the wrong reason. No model is invoked
anywhere in this aspect; there is no BYOK seam to stub because nothing calls a model.

**Train/held-out boundary:** not applicable — this aspect trains nothing and evaluates no
checkpoint. Nothing here can leak, because no split exists yet. The ingestion slice that creates
one inherits the obligation.

**Manual verification:** `uv run whetstone verify --task <fixture> --patch <fixture>`, once against
a fixing patch and once against a cheating one; confirm the verdicts and the exit codes.

## 4. Environment, Determinism & Locality

- **No environment variables are required**, and no credentials. Nothing in this aspect reads a
  key, because nothing calls a model.
- **Pinned for reproducibility:** `PYTHONHASHSEED=0`, `PYTHONDONTWRITEBYTECODE=1`, sandbox-local
  `TMPDIR`, `-p no:cacheprovider`, `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`, explicit `-c` config path.
- **What determinism is *not* claimed.** The sandbox does not make the repository under test
  deterministic. A task whose own tests are timing-dependent is a flaky task; the honest handling
  is P3's retry-then-`UNVERIFIED` policy, not a pretence the sandbox removed the flakiness.
- **Locality:** everything runs on this machine. The verifier makes no outbound call — it *denies*
  the network to the process under test. Nothing leaves the box.

## 5. Edge Cases & Error Handling

Every failure below has a named outcome. **There is no silent pass and no fallback that grants a
reward.**

| Condition | Outcome |
|---|---|
| `sandbox-exec` missing / not darwin | Raise `UnsupportedPlatform` — never run unsandboxed |
| Sandbox denies something unexpectedly | `UNVERIFIED` with the denial recorded, not `FAIL` |
| Pytest times out | `UNVERIFIED` — could not check ≠ patch is wrong |
| Patch does not apply | `FAIL` — the policy produced an invalid patch; that *is* a wrong answer |
| Patch touches a path in `test_blobs` | Rejected before execution, distinct from a test failure |
| A `test_blobs` path is missing from the checkout | `UNVERIFIED` — the task is malformed, not the patch |
| Executed set ≠ `fail_to_pass + pass_to_pass` | `FAIL` (cheat 7) with the mismatch in the message |
| Skipped count > 0 | `FAIL` |
| Pytest emits unparseable output | `UNVERIFIED`, never a default `PASS` |
| Empty verdict set | `UNVERIFIED`, by the reduction |
