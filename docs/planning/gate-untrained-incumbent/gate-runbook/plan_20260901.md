## Testing strategy

- Guard tests only (no unit tests in this aspect — the sheet is a document; the guard is its
  test). The new pin is the acceptance test: it fails on master's sheet, fails each assertion
  on the stub sheet, and passes on the edited sheet.
- Anti-vacuity: the new pin asserts the materialization block exists and its path is absolute
  (an empty parse passes nothing); the existing anti-vacuity test
  (`test_the_parse_really_reads_the_sheets_commands`, 158-170) stays green.
- Determinism: the guard is pure text parsing; no network, no clock.

## Environment, determinism & locality

- No env vars, no keys, no external tools. The sheet's commands are not executed by the
  suite (they are parsed); the operator runs them post-merge on the GPU machine.
- Nothing leaves the box: the sheet is instructions; the materialized checkpoint is a local
  provenance file (no weights are copied — `write_baseline_checkpoint` writes provenance
  only, sft.py:457-496).

## Edge cases & error handling

| Case | Outcome |
|---|---|
| Operator runs the sheet before aspect 1's code is merged | The fixture-verification step (Step 1) fails first — the gate suites on master's gate do not include the dispatch tests, and the gate refuses nothing about an untrained candidate; the sheet's own ordering makes the machinery check precede the spend |
| The materialization path already exists with files | `write_baseline_checkpoint` refuses by name (sft.py:472-477) — the sheet's materialization step says the directory must be empty |
| § 3 checkpoint materialized later under its own path | Independent; the sheet's § 3 boundary sentence names the separation |
| A rejected candidate | Unchanged halt condition 3 — the response is another night, never a looser comparison |
| `feat-p3-promotion-gate` named anywhere else in the repo | Phase 3's grep finds it; if it is another sheet's pinned worktree, that sheet's own guard owns it — report, don't edit |
