## Testing strategy

- Unit tests as Phase 1; integration via the existing gate harness (`run_gate` + stub engine
  + real fixture checkpoints + real held-out document + real verifier fixtures).
- **Gate-honesty analogues of the adversarial rule.** The reward path does not move, so the
  adversarial shape here is the gate's: (a) the dispatch test is RED on master because
  master's engine *is* the credulous variant (always stacks an adapter) — the test exists to
  keep the untrained side honest; (b) the refusal test's converse is a gate that accepted an
  untrained candidate, which would compare on a constant digest that cannot discriminate
  bases — the fixture asserts the refusal, watched failing on a version without it (Phase 1
  RED covers this, since the refusal does not exist on master).
- Determinism: no generation, no network, no clock — fixtures only; the dispatch test is
  pure kwargs capture.
- Anti-vacuity: the dispatch test asserts the captured kwargs differ between the two shapes;
  the decision-table test asserts all four outcomes are exercised (not just promoted).

## Environment, determinism & locality

- No env vars, no keys, no external tools. `mlx_lm` imports stay function-local; tests run
  under plain `uv sync`.
- Nothing leaves the box: fixtures and stub engines only; no weights are loaded, no held-out
  data is touched (the held-out document in tests is a fixture document over fixture ids).
- Determinism: the aspect adds no unpinned input; seeds, digests and recorded_on semantics
  are untouched.

## Edge cases & error handling

| Case | Outcome |
|---|---|
| Untrained checkpoint passed as `--candidate` | `UntrainedCandidate`, exit 2, message names the side and path (the honest direction: the constant digest cannot identify the base) |
| Untrained checkpoint passed as `--incumbent` | Scored through the base-only load; decision table applies; `UNVERIFIED` still never a win (`decide` untouched) |
| Two untrained checkpoints in one run | Not reachable: the candidate side is refused first; the stub keying keeps the constant digest distinct in fixtures |
| `mlx_lm` changes `adapter_path=None` semantics | The dispatch test fails (captured kwargs) rather than silently loading the wrong weights |
| Weights root lacks the untrained base's revision | `NoBaseWeights` (existing, unchanged) — exit 2 |
| Trained checkpoint (all existing paths) | Byte-identical behaviour; existing suite proves it |
